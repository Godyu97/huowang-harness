# GeoPro 产品需求文档（PRD）

> v3.0｜2026-11-17｜面向中国大陆小 B 自助与团队经营｜执行基线：M0；M1/M2 已拆解为后续增量。

## 1. 产品定义

围绕客户的真实购买问题，监测品牌在 AI 回答中的提及、推荐、引用和事实准确性，把观察缺口转成有依据的内容动作，公开核验后进行同口径复测。核心价值与成功目标见 [Intent](00-PRODUCT-INTENT.md)，来源取舍见 [功能评审](01-项目立项与方案审查总览.md)。

首发目标用户是中国大陆中小 B2B 品牌负责人及市场运营。个人用户可走同一路径；代理商与多客户经营逐步开放。全局默认简体中文、人民币金额展示、品牌报表日历 Asia/Shanghai；系统可保留真实时间偏移，不因开发者机器时区改变日统计。

## 2. 用户主旅程

```mermaid
flowchart LR
  A[建品牌与确认问题] --> B[预览渠道范围和预算]
  B --> C[API采样 / 消费者人工存证]
  C --> D[查看原文与独立指标]
  D --> E[确认问题与优化任务]
  E --> F{事实齐全?}
  F -->|否| G[补证并确认事实]
  G --> H[确认Brief并生成小批次草稿]
  F -->|是| H
  H --> I[逐稿审核与导出]
  I --> J[用户发布与公开核验]
  J --> K[同口径复测与报告]
  K --> E
```

首次报告不等待事实库完善；只有进入内容生产才要求该稿所需事实、主页面和承接动作齐备。没有官网可以建档、采样和诊断；正式内容闭环需要一个可确认归属并可核验的公开页面。没有可用渠道可以准备资料，不能宣称真实监测已上线。

用户可以只监测、只执行人工修改或不生成内容；产品仍保留这些活动。北极星所称完整闭环必须有证据、内容动作、核验和可比复测，不把单次使用强行算成闭环。

## 3. 信息架构与页面合同

页面标识是逻辑标识，不要求具体 URL 或代码目录。

| 页面 ID / 一级入口 | 核心任务及主操作 | 关键内容与状态 |
| --- | --- | --- |
| PAGE-01 首页/身份/品牌引导 | 开始体验、登录、继续草稿 | 产品能力边界、演示标签、三步建档；无真实额度策略不写“免费无限” |
| PAGE-02 总览 | 看下一步、启动/继续运行 | 品牌与范围、提及/推荐/官网引用、质量、最近回答、最多 3 条建议、阻塞 |
| PAGE-03 品牌资料 | 确认事实、管理问题 | 品牌实体、来源和事实、问题簇、题集预览；M1 素材/模板/资料复用 |
| PAGE-04 AI 回答与监测 | 运行、人工存证、查看原文 | 任务进度、题单、轨道/渠道筛选、证据详情、引用和纠错；M1 计划与竞品来源 |
| PAGE-05 优化任务 | 接受建议、补证、记录完成 | 证据、假设、目标页、步骤、优先理由、负责人、完成依据和复测入口 |
| PAGE-06 内容与发布 | 确认 Brief、生成、审核、导出、回填 | 计划/批次/稿件/发布四种对象分别计数；M1 多渠道日历与维护 |
| PAGE-07 复测与报告 | 发起复测、看差异、下载 | 可比性、窗口、共同题、逐题分母、内容生效点、结论限制；M1 业务反馈 |
| PAGE-08 设置（次级） | 看能力、额度与数据管理 | 当前可用通道、限制、实际费用、数据导出/删除；M1 团队；M2 连接/客户权益 |

M0 显示与当前用户有关的功能，M1/M2 不放大量不可点击菜单。列表支持关键词、状态、日期、问题簇筛选及结果计数；详情返回保留筛选与草稿。批量动作先显示范围与逐项结果，部分失败不重做已成功项。

共同交互状态：首次空态、加载、无匹配结果、部分成功、待复核、未知/不支持、权限不足、额度不足、外部不可用、已被新版本取代。每态给当前事实和下一步；不以加载中的示意数冒充真实结果。错误信息应让用户知道是否可以重试、是否可能已经发生费用。

## 4. 角色和权限

M0 只有负责人本人，不能让 AI 成为审批者。单人可进行两次独立确认：事实确认与内容批准。M1 才引入团队分工；双人审核是可选组织策略，启用后强制执行。

| 角色 | 事实/题集 | 监测/分析 | 创作/审批/发布 | 组织/预算/导出 |
| --- | --- | --- | --- | --- |
| 品牌负责人（M0） | 编辑与确认 | 运行、纠错、看原文 | 创作、显式自审、导出、手动核验 | 管理自己品牌和预算；导出自己数据 |
| 运营（M1） | 编辑草稿、提补证 | 已授权品牌运行与查看 | 写稿、提交审核、回填发布；不可批准事实/内容 | 不改成员/预算；导出需独立授权 |
| 分析者（M1） | 题集/实验编辑 | 查看证据、修订分析与诊断 | 创建任务，不默认批准内容 | 生成报告；下载按导出授权 |
| 审核者（M1） | 确认事实（需事实权限） | 查看必要证据 | 内容批准（需内容权限），启用双人时不能审本人稿 | 无默认成员/预算管理 |
| 只读成员（M1） | 读获准公开资料 | 看获准报表 | 不编辑、不审批、不发布 | 私密附件和导出需另外授予 |
| 工作区负责人（M1） | 可分配品牌权限 | 管理范围 | 不得绕过双人策略 | 邀请/撤销、品牌范围、预算 |
| 代理项目经理（M2） | 取决于品牌委托 | 取决于品牌委托 | 取决于品牌委托 | 委托范围内交付，不能自动访问所有客户 |
| 能力/平台维护者 | 管能力和运行元信息 | 默认不读客户正文 | 无默认客户内容批准权 | 不因维护身份获得客户私密资料权限 |

跨角色时权限取实际授权，角色名不构成跨品牌通行证。对外公开动作还需具体账号/动作授权。报告和附件与业务数据遵守相同访问范围。

## 6. 首发默认值与变更边界

| 参数 | M0 默认 | 扩展与限制 |
| --- | --- | --- |
| 活跃品牌 | 每负责人 1 个 | M1 团队多品牌，按明确权益开放 |
| 快速核心题 | 默认 6，最少 3，最多 10；至少 3 个非品牌题 | M1 40+10 模板；基线冻结后不能覆盖题目 |
| 竞品 | 0–3 个，建档可跳过 | M1 最多 5 个并冻结比较集合 |
| 采样范围 | 1 个官方 API + 1 个消费者入口人工存证路径 | 产品能力门禁要求两者；用户单次可只选一轨，分别报告 |
| 快速重复数 | 每题每通道 1 次，可选 1–3 | 单次只作观察，M1 按正式计划累计重复 |
| 消费者快速题单 | 默认取核心非品牌题中的 3 题 | 可选更多，按人工能力和成本；不与 API 混算 |
| 官网/自有页检查 | 单次最多 5 个指定公开 URL | 无官网不阻塞监测；受限页可人工提供证据 |
| 内容生成批次 | 默认 1 份，上限 5 份已确认 Brief | 不以篇数作为效果目标；模板/素材可后续复用 |
| M0 输出模板 | 事实 FAQ、场景方案、可核验比较三类 | 比较资料不足转补证；不能臆造竞品参数 |
| 交付范围 | 主页面修改包 + 1 个外部渠道素材包 | 允许主页面就是该自有外部页，去重为一个实际发布目标，不硬造第二个页面 |
| 导出 | Markdown、HTML、manifest、公开来源、发布清单、授权图片（可选） | M1 增加可编辑文档；不是发布回执 |
| 采样重试 | 最多 2 次额外尝试，受预算和安全重试条件限制 | 费用/执行未知先核对；绝非无限免费重试 |
| API 成本上限 | 用户明确确认，供应商金额未知则不得自动执行 | 不预填不存在的价格，不沿用点数兑换比例 |
| 复测 | 立即探索复测 + D+7 站内待办 | M1 14 天基线及 D+7/14/28 正式检查点 |
| 品牌统计时区 | Asia/Shanghai | 变更聚合时区创建新口径，不回写旧报告 |
| 题集/事实/内容/报告 | 版本化、历史只读 | 修改生成新版本，删除按公共数据规则显示证据缺失 |
| 通道验证有效期 | 默认 30 天，变化即时失效 | 这是内部验证周期，非供应商能力承诺 |

“默认”是可用的开发输入，不是等待用户再做几十项决定。可配置参数的变更必须记录版本，不能为提高分数追溯修改已完成运行。

## 7. 内容质量及输出边界

硬门禁是核心主张有有效事实、公开许可成立、内容版本已批准、必要标识可交付。结构建议是首段回答问题、列清参数/适用边界、来源与日期可查、段落可独立理解。它们不能被包装成已证明的算法偏好，不强制每段重复品牌，也不把任意 linter 分数当推荐概率。

没有事实材料可以先做诊断、补证和写结构提纲；不得输出看似真实的客户案例、资质、价格或性能。产品内 AI 只能提出建议和待确认草案，不能自行批准、公开发布、变更预算或授予权限。

## 8. 商业与非功能验收需求

M0 为受控试点额度；首页 CTA 用“开始体验”。不虚构免费期限、用户数、平台覆盖、营收和提升效果。单次操作展示预计数量/成本、实际消耗和失败处理；平台供应商成本与客户收费分开。

新项目需实现持久数据、可恢复运行、资源隔离和不重复消耗。产品体验目标：任务提交后先显示登记结果和可恢复进度；普通页面响应和运行时延由新项目实测记录，不承诺外部模型固定秒数。375/768/1440 宽度下主流程可操作，键盘焦点、字段标签、错误说明完整，正文对比度达到常用 AA 基线。

所有目标都须实际验收，不能只截图；无需为本文绑定某种前端、服务端或数据库方案。详见 [里程碑与验收计划](05-里程碑与验收计划.md)。

## 9. 不进入开发基线的内容

不做“保证 AI 第一名”、无法证实的模型收录统计、批量洗稿换品牌、媒体采购交易、自动操纵评价、未经授权采集或发布、默认视频矩阵生产、无上限自主 Agent。M0 不做支付、复杂团队、外部账号托管或插件采集。旧技术 Spec 与工期估算已归档，不能作为新项目的强制约束。
