## 一、 产品目标与用户角色权限矩阵

### 1.1 产品核心设计原则
1. **以购买问题为中心，而非以发稿数量为中心**：一切监测、诊断和创作均围绕影响客户成交的“高意图购买问题簇（Intent Cluster）”展开，拒绝生产无业务承接的水文。
2. **先核实事实，再生成内容**：无批准事实不生成核心参数主张；缺少客户材料时优先触发“补证访谈任务”，绝不允许大模型编造能力、案例或资质。
3. **API 趋势与真实消费者端表现分账展示**：严禁将火山方舟/百炼 API 监测数字直接包装成“豆包 App / 夸克 App 排名”，保障交付报告经得起客户老板随时拿出手机现场抽查。

### 1.2 五大角色与权限边界（RBAC + 项目授权）

| 角色名称 | 典型使用者 | 核心职责与高频操作 | 严格权限边界 |
| :--- | :--- | :--- | :--- |
| **品牌管理员**<br>`brand_admin` | 甲方市场总监 / 品牌负责人 | 确认客户成功计划（CSP）、审批品牌事实库、审批外发内容版本、确认渠道发布、签收阶段报告、录入有效线索反馈 | 仅限本企业租户下获授权品牌；事实批准 ≠ 内容发布批准 |
| **内容与增长运营**<br>`content_operator` | 乙方代运营专员 / 甲方内容编辑 | 维护品牌资料与补证任务、撰写内容简报（Brief）、AI 辅助创作与修订、导出渠道素材包、使用浏览器插件采集 C 端样本与回填发布链接 | 仅访问被分配品牌；无权自行批准事实或越权触发官方 API 公开发布；无权查看平台底层供应商密钥 |
| **GEO 数据分析师**<br>`geo_analyst` | 策略分析师 / SEO&GEO 专家 | 设计与冻结 40+10 问题集、配置采样计划、复核实体消歧与 CoT 思考链归因、注册对照实验、撰写复盘策略记录 | 可新增 `analysis_version` 修正误判，**严禁修改或覆盖原始回答原文（Observation）** |
| **代理商项目经理**<br>`agency_pm` | Agency 客户成功经理 / 交付主管 | 跨客户项目进度看板、采样配额与预算管控、工时记录、生成月度结案报告、跟进续费与增购 | 必须同时具备代理商成员身份与甲方显式授予的 `project_grant`（含品牌范围与有效期）；授权撤销立即阻断访问 |
| **平台系统运维**<br>`platform_ops` | SaaS 平台技术支持与运维 | 监控通道健康度、限流告警、死信队列恢复、供应商账单对账 | 默认不可查阅客户私密事实附件；排障临时访问须走独立审批并留存不可篡改审计日志 |

## 二、 统一产品信息架构（6 大核心工作台模块）

为解决原有多份文档中“9 页面”与“6 入口”冲突的问题，产品控制台统一收敛为 **6 大一级业务模块 + 1 个工作区管理中心**（统一路由前缀 `/w/[workspaceId]/b/[brandId]/...`）：

| 一级导航模块 | 路由路径 | 首屏核心解决的业务问题 | P0 核心功能点 | P1/P2 演进能力 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 项目总览**<br>`Overview` | `/overview` | 目标达成了吗？本周最紧急的阻塞和行动是什么？预算消耗正常吗？ | 客户成功计划（CSP）目标状态卡、四层漏斗核心 KPI、待办与阻塞提醒（缺证据/待审批/异常暂停）、通道预算消耗进度 | 多品牌横向健康度对比大盘（Agency 视图） |
| **2. 品牌底座与问题集**<br>`Foundation` | `/foundation` | AI 应该知道关于我的哪些准确事实？我们要监控哪些高价值购买问题？ | 品牌实体与同名消歧规则、自有域名与各平台账号归属登记、**品牌事实库（Fact Vault）与有效期审批**、**购买问题簇与 40+10 题集版本管理** | 竞品事实对比档案、行业标准问题模板库一键导入 |
| **3. 双轨监测与证据库**<br>`Monitoring` | `/monitoring` | 各大 AI 怎么回答这些问题？为什么推荐竞品而不推荐我？引用了谁的网页？ | 采样日历与费用预估器、L1 官方联网 API 自动调度、**L2 浏览器采集助手任务同步**、原始回答与 **CoT 思考链查看器**、原生引用 URL 与信源归属分析、人工标签纠错 | 自动化高频异常波动飞书/企微告警、细粒度地域分布式节点对比 |

| **5. 渠道分发与维护**<br>`Distribution` | `/distribution` | 批准的内容发到哪里了？是否真实公开可见？有没有被删改或事实过期？ | 官网改造包导出、**1+3 渠道变体适配与素材包（`manifest.json` + 富文本一键复制）**、微信公众号草稿 API 直推（P0 候选/P1）、人工发布 URL 回填、线上可见性与正文一致性巡检 | WordPress/Git CMS 连接器、抖音/快手/B站官方 API 发布连接器 |

## 三、 核心业务模块详细需求规格

### 3.1 客户成功计划（Customer Success Plan, CSP）—— 立项即冻结验收标准
在启动任何采样和写稿前，必须在系统中建立并由客户确认 CSP，杜绝后期扯皮：
- **目标类型二选一或组合**：
  - `可见性目标（Visibility Goal）`：适用于重品牌心智客户，考核指定目标 AI 产品在固定高意图非品牌题中的推荐率提升与事实准确率。
  - `业务线索目标（Lead Goal）`：适用于重获客转化客户，以“可观察的 AI 关联有效咨询数”为北极星指标，推荐率与引用率作为前置过程指标。
- **必填冻结项**：优先购买场景（1-3 个）、目标影响的 AI 产品清单（如：DeepSeek 网页/App + 腾讯元宝 + 豆包）、固定核心题集版本、有效线索判定标准（行业/规模/需求真实性）、客户方资料对接人、可修改的官网范围与渠道账号、观察周期与停止条件。

### 3.2 购买问题簇与 `40 + 10` 标准问题集设计
每品牌默认配置 **40 道冻结核心题 + 10 道动态探索题**，问题必须源于真实销售录音、售前咨询、客服工单与选型痛点：

| 题组分类 | 数量 | 商业意图与示例（以连锁门店设备管理 SaaS 为例） | 计入核心指标范围 |
| :--- | :---: | :--- | :--- |
| **A1. 品类发现题**（非品牌） | 10 题 | 泛需求入围：“适合 50-500 家连锁餐饮门店的设备巡检报修系统有哪些？” | 计入主面板推荐率、提及率、SoV |
| **A2. 场景方案题**（非品牌） | 10 题 | 痛点解决：“跨省多门店冷链设备温度异常怎么实现自动预警和派单？” | 计入主面板推荐率、提及率、SoV |
| **A3. 购买约束/高意图题**（非品牌） | 10 题 | 成交临门一脚：“支持全内网私有化部署、带三级权限审批的设备管理系统怎么选？大概多少钱？” | **标记为“高意图子集（High-Intent）”单独高亮展示**，同时计入 30 题非品牌总推荐率 |
| **B. 竞品直接比较题** | 5 题 | 优劣势核验：“[本品牌] 和 [竞品X] 在私有化部署成本和硬件兼容性上有什么区别？” | **独立报表展示**（不混入非品牌自然发现推荐率，防刷分） |
| **C. 品牌事实核验题** | 5 题 | 防幻觉与纠错：“[本品牌] 的售后服务网点覆盖哪些城市？标准版收费模式是什么？” | **独立考核“品牌事实错误率”** |
| **D. 轮换探索题** | 10 题/周 | 捕捉新兴长尾问法与热点问题，每周可替换，发现高价值缺口后可在下一周期升格 | 仅用于机会挖掘，不混入核心基线趋势线 |

- **购买问题簇（Intent Cluster）聚合**：将语义近似的 3-5 道题归入同一个“购买问题簇”，每个问题簇绑定 **1 个唯一官网主落地页（Primary Page）** 和 **1 个明确业务承接动作（如：预约私有部署架构师演示）**，防止内部多个近似页面互相稀释权重。

### 3.3 双轨三层监测与思考链（CoT）解析需求
1. **L1 服务端官方联网 API 自动监测（高频趋势轨）**：
   - 首版接入 **火山方舟联网搜索插件（Doubao 系列模型）** 与 **阿里云百炼联网搜索（Qwen 系列模型）**（以及可选 DeepSeek API + 标准搜索参考管线）。
   - 默认频率：基线期与观察期每日早、中、晚 3 个分散时间槽位，全新无历史上下文会话，绝不注入品牌知识库 Prompt。
2. **L2 浏览器合规辅助采集插件（真实消费者端核验轨）**：
   - 针对 **豆包网页版、DeepSeek 官方网页版、腾讯元宝网页版、Kimi 网页版、百度 AI 搜索**。
   - 交互流程：运营人员安装 `GeoPro Capture Extension` → 登录平台拉取今日待核验高意图题单（默认每品牌每周 2-3 次，每次抽检 15-20 道高意图核心题） → 插件在已打开的目标 AI 网页输入框自动填入标准问题 → 运营确认发送（如遇平台验证码由人工正常点选通过） → 回答生成完毕后点击插件“一键存证” → 自动提取 **回答全文 Markdown + 深度思考过程（CoT Trace） + 参考资料卡片标题与真实 URL + 视口带时间戳截图** 上传至平台证据库。
3. **CoT 思考链与淘汰归因提取（大陆特色核心能力）**：
   - 当样本包含 `reasoning_text` 时，分析管线自动抽取三类结构化标签：
     - `采纳依据（Positive Signals）`：模型明确认可本品牌的维度（如“查到某篇知乎评测提及支持国密加密”）。
     - `淘汰/质疑原因（Rejection Reasons）`：`missing_parameter`（缺关键参数）、`outdated_info`（资料年份过旧）、`marketing_fluff`（被模型判定为广告软文不予采信）、`price_opaque`（无定价说明）、`competitor_stronger_proof`（竞品有明确案例数据）。
     - `错失检索（Retrieval Miss）`：思考链列出已阅读的 N 篇参考网页中完全未出现本品牌信息（说明需补强对应亲和渠道分发）。

### 3.4 中国大陆“AI 友好型（AI-Friendly）”内容工程规范（内置于 Studio 编辑器）
为确保生产的内容真正能被豆包、DeepSeek、元宝、Kimi 抓取、切块并高置信度采信，Studio 工作台强制执行 **“先确认内容简报（Brief）→ 再生成草稿 → 通过六维 AI 友好度校验 → 方可提审”**：

1. **内容简报（Content Brief）前置门禁**：生成正文前，必须填写并确认：`目标问题簇与受众`、`当前 AI 回答缺口与 CoT 淘汰原因`、`核心结论与产品不适用边界`、`绑定的已批准 fact_id 列表`、`主发布页与分发渠道`、`文末业务承接入口`。若缺核心事实证据，自动转为 `补证任务` 指派给甲方业务接口人。
2. **内置六大 AI 友好型内容结构校验规则（AI-Friendliness Linter）**：
   - **准则 1：首屏直答摘要块（Answer-First TL;DR）**：正文前 200 字内必须给出针对核心购买问题的明确结论句与适用条件摘要。
   - **准则 2：Chunk 语义自包含（Self-Contained Chunks）**：每个二级标题（`H2/H3`）下的核心段落（300-600 字）必须显式包含**完整品牌名 + 产品品类词**，减少代词“我们/该系统”指代不明，确保 RAG 切片后独立语义完整。
   - **准则 3：结构化参数与选型对比表（Structured Tables & FAQ）**：涉及规格、版本差异、竞品选型维度时，优先输出标准 HTML `<table>` 与 `Q&A` 问答对，便于大模型精准抽取键值。
   - **准则 4：诚实适用边界声明（Honest Boundary）**：必须包含“适用客户条件”与“不建议选用的场景/前置限制”，消除营销软文特征，大幅提升 DeepSeek/Kimi 推理采信权重。
   - **准则 5：可核验信任锚点与新鲜度时间戳（Trust & Freshness）**：显式标注 `资料核验更新日期：YYYY-MM-DD`、数据出处、公开客户案例背景及测试条件，杜绝无来源绝对化用语（同时符合中国《广告法》极限词过滤）。
   - **准则 6：合规 AIGC 标识与事实一致性锁（Compliance & Fact Lock）**：文中所有数值、价格、地域范围与 `fact_id` 自动比对；导出或发布时自动附带符合《人工智能生成合成内容标识办法》的声明与元数据标识。

### 3.5 `1 + 3 + X` 渠道分发与状态管理
- **`1` 客户官网改造**：
  - 自动检测官网是否在中国大陆网络下 **首字节/正文直出 < 1.5s**、是否因纯 CSR（客户端渲染 JS 空壳）导致 AI 实时搜索爬虫抓取空白、robots.txt 是否误拦截主流 AI 搜索爬虫（如 Bytespider、Baiduspider、Sogou、Bingbot 等）、`canonical` 与 `JSON-LD (Organization/Product/FAQPage)` 是否规范。
  - 输出标准化《官网单页改造包》（含 HTML/Markdown 正文、Metadata、JSON-LD 代码片段、内链与百度/IndexNow 提交清单）。
- **`3` 首版核心外部自媒体分发（P0 聚焦打透）**：
  1. **微信公众号**：支持生成微信白名单内联样式 HTML 预览包；支持已授权公众号调用官方草稿箱接口一键推送至后台草稿箱（`D 级草稿协作`），由客户管理员在微信后台最终确认群发/发布并回填永久链接。
  2. **知乎（机构号回答/专栏）**：针对目标高赞行业选型问题或新建专业测评专栏，生成知乎纯净 Markdown + 表格转高清信息图辅助包，人工发布后回填回答独立 URL。
  3. **百家号（企业号）/ 今日头条**：生成高结构化问答式图文素材包（`manifest.json` + 图文 + 原创/AI 声明清单），人工发布后回填远端作品 ID 与公开 URL。
- **线上巡检验证**：回填 URL 后，Worker 自动发起匿名访问核验，区分 `verified_public`（公开且关键事实一致）、`mismatch`（平台删改导致事实偏差）、`access_limited`（需登录或风控拦截，转人工复核），绝不把草稿链接当成已上线。

## 四、 `metrics-v2` 核心指标合同（统一口径）

延续并升级 `metrics-v1`，所有报表必须同时展示 **比率 + 分子/分母 + 覆盖率 + 分析版本号**：

| 指标层级 | 指标名称 | 精确计算公式与口径说明 | 防误读护栏要求 |
| :--- | :--- | :--- | :--- |
| **采样质量护栏** | **条件合格覆盖率** ($E/P$) | $E \div P$（$P$ 为冻结计划槽位数；$E$ 为完整返回且验证触发联网搜索的合格回答数） | 正式前后期对比要求总体 $E/P \ge 90\%$ 且单题覆盖 $\ge 80\%$；低于门槛仅标“探索观察” |
| **L2 引擎采纳层** | **自有信源原生引用率** | 含至少 1 条自有官网或自有认证平台账号原生引用 URL 的合格样本数 $\div C$（$C$ 为引用字段完整可观察样本数） | 同时展示引用可观察率 $C/E$；共享域名（如 `zhihu.com`）必须精确匹配到客户自有账号/回答 URL 才计入自有引用 |
| **L2 引擎采纳层** | **第三方正向支持率** | 引用了非自有第三方页面且正文经核验正向支持本品牌的样本数 $\div$ 可判断支持性样本数 | 页面抓取受限记为 `待验证`，不计入负面或零支持 |
| **L2 引擎采纳层** | **品牌事实错误率** | 经复核存在参数/价格/地域事实错误的回答数 $\div$ 已复核含本品牌的回答数 | 优化核心护栏：不允许以制造错误夸大事实换取推荐率上涨 |
| **L3 购买推荐层** | **非品牌题推荐率**（核心） | 对 30 道固定非品牌题，先算单题推荐率（明确列为适合选项样本数 $\div J_r$），再对固定共同题做**等权均值** | **高意图 10 题子集**独立并列展示；负面提及或仅复述题干不计推荐；变化统一用**百分点（pp）**表述 |
| **L3 购买推荐层** | **竞品提及份额（SoV）** | 本品牌确认提及合格样本数 $\div$ 固定竞品集合内各品牌确认提及合格样本数之和 | 同一回答内某品牌出现多次仅计 1 次；注明为“题集样本声量份额”，非真实市场占有率 |
| **L4 业务转化层** | **可观察 AI 关联有效线索数** | 统计周期内符合客户冻结有效标准且具备 AI 关联证据的去重线索数 | 严格按三档证据强度分列：① 技术可识别 AI Referrer 会话转化；② 专属落地页/组件引导转化；③ 销售登记客户明确自报“看豆包/DeepSeek 推荐而来”。绝不乘以系数推算全量不可见转化 |

## 五、 首轮种子客户标准交付 SOP（5 步法）

1. **Week 1 冻结目标（CSP 签约）**：选定 1-3 个高利润核心产品场景 → 冻结 40 道购买问题与目标 AI 入口（如 DeepSeek + 元宝 + 豆包） → 明确有效线索定义与官网可改权限。
2. **Week 2-3 基线采样与深度盘点（并行不抢跑）**：启动连续 14 天同条件基线采样；同步开展官网技术可读性审计、客户业务专家访谈补证、建立审批通过的品牌事实库、撰写首批内容简报（此阶段准备草稿，但**严禁提前修改实验目标页污染基线**，严重事实报错除外）。
3. **Week 4-5 首批“1+3”内容资产组合上线**：基线满 14 天冻结快照后，集中上线每品牌 **不少于 3-5 项高密度内容改动**（例如：1 个官网核心场景解决方案页重构 + 1 个私有部署参数与 FAQ 页 + 2 篇微信公众号深度选型文 + 2 篇知乎高意图问答/百家号行业解析），完成公开可见性验证并启动观察计时。
4. **Week 6-9 持续复测与线索对账（D+7 / D+14 / D+28）**：保持同条件采样，观察引用采纳、CoT 评价转变与推荐率变化；每周与甲方销售核对咨询线索台账，将销售听到高频新顾虑反哺至下一轮简报。
5. **到期复盘决策**：按预设运营决策表自动转化为下一周期行动工单（如：“已被引用但未获推荐 → 补强适用场景量化案例”；“已获推荐但无线索 → 优化落地页首屏预约入口与表单摩擦”）。
