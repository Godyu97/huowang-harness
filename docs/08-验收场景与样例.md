# 验收场景与样例

> v3.0｜产品验收设计；并非已运行的软件测试。功能验收共 78 项，分别位于各级 SPEC；阶段验收另见 05。

## 1. 合成品牌与主流程

演示品牌“北岸设备”，网站使用保留示例域名 https://beian-equipment.example；竞品“远帆设备”。所有记录 is_demo=true，页面和导出标“演示数据”。

准备三个非品牌题：“30 家门店如何管理设备巡检？”“支持离线巡检的设备管理产品怎么选？”“预算有限的连锁门店怎样比较报修系统？”以及一个比较题“北岸设备和远帆设备有什么不同？”。比较题不进自然发现主指标。

准备三条事实：支持离线巡检（附合成产品说明）；价格按门店数报价（附条件及合成报价说明）；服务范围（附日期）。这些只是测试事实，不得用于真实营销。

走查：建档 → 题集预览 → API fixture 运行（3 成功 1 失败）→ 消费者 fixture 人工存证 → 原文与独立标签 → 一项 FAQ 缺口任务 → 确认事实与 Brief → 两篇成功一篇失败的小批次 → 重试失败项 → 逐稿审核 → Markdown/HTML 包 → 草稿链接核验失败 → 合成公开页核验 → 同范围复测 → 报告 HTML/JSON。

这条路径覆盖局部失败恢复，仍需用真实渠道/真实试点单独执行阶段门禁。不能将示例网站当作真实发布目标。

## 3. 机器样例如何使用

- [metric-cases.json](fixtures/metric-cases.json)：10 个金样，包含分层分母、归属未知、零分母、题等权、共同题、质量门槛、线索去重、日期窗口和独立标签。
- [report-example.json](fixtures/report-example.json)：三个共同题、前后各一次、推荐 0/3→1/3 的演示快照；值可从逐题记录复算。所有 observation 和 content ID 为显式合成引用。

新项目需要另做真实持久化、页面、权限及外部能力验证；本目录检查脚本只复算其中的数学/日期案例，并核对引用、ID 和依赖。语义分类两例作为业务验收输入，由实现与人工复核测试，而非让文档检查脚本冒充模型分析测试。

## 4. 状态与错误的人工走查

各主要页面检查首次空态、加载、无匹配、部分成功、权限失效、预算不足、外部能力不可用、未知引用、历史版本和证据被删除。检查返回列表的筛选保留、刷新后的运行进度、批次取消后的晚返回、待核对费用处理。

375px 检查主要按钮可点击、表格可横向查看；768px 与 1440px 检查不遮挡状态/分母；键盘可完成引导、筛选、原文展开、审核与导出。不用装饰图片或过量动效掩盖数据质量提示。

## 5. 外部验证记录模板

| 字段 | 应记录内容 |
| --- | --- |
| 能力/版本 | 观察对象、入口、模式、采集方式、模型版本或未知 |
| 验证条件 | 时间、目标/实际地区、会话、联网要求、账户可用权限 |
| 执行范围 | 固定题集、槽位数、成功/失败/未知、实际耗时 |
| 证据 | 原回答、引用完整性、联网发生依据、消费者存证 |
| 费用 | 预计上界、实际、待核对；不要写密钥/账号密码 |
| 结论 | 哪些能力通过、哪些不支持、何时过期、退化处理 |
