# 中国大陆 GEO：调研复核与产品方向

> v3.0｜查阅日期 2026-11-17｜本次复核公开材料和项目内调研，没有真实账户 PoC。本文只推导产品功能，不做技术选型。

## 1. 证据强度

| 级别 | 定义 | 本次可用性 |
| --- | --- | --- |
| REFERENCE | 原型/历史调研中的设计或历史观察 | 已阅读，不能提升为本轮实测 |
| PUBLIC | 官方文档、产品自述或研究摘要 | 下表列出；声明能力不等于账户可用 |
| VERIFIED | 本产品按固定采样条件取得可复查结果 | 本轮没有，须由实施任务取得 |
| OUTCOME | 真实用户闭环及业务反馈 | 本轮没有，须由试点取得 |
| DESIGN | 依据上述信息作出的设计决定 | 全部 M0–M2 需求；不是已发生事实 |

不继续沿用旧报告里无法支撑产品承诺的用户规模、固定毛利、续费率判断和“某平台最高权重”描述。“前沿”在本版指问题意图、证据可追溯、实体准确性、内容维护、重复测量和业务反馈之间的连接，属于产品方向判断，不宣称行业第一。

## 3. 对项目既有调研的保留与修正

| 旧结论 | 新版处理 | 理由与需求 |
| --- | --- | --- |
| 以高意图问题和四层结果组织经营 | 保留 | 发布成果、引擎采纳、站点访问、业务咨询分层；R-M0-03/12、R-M1-07 |
| API 与消费者端分轨 | 强化 | 同厂商品牌也不是同一观察对象；R-M0-04/07 |
| 元宝必然最高权重公众号，DeepSeek 固定偏好知乎等 | 降为假设 | 用题集×入口×时间的实际引用分布检验；R-M1-02 |
| 官方 API“100% 合规”或人工插件“零封号” | 删除绝对承诺 | 文档与用户操作不代表所有使用条件已满足；能力状态需可失效 |
| 单人 15 分钟完成跨平台大量采样 | 删除未实测效率 | M0 记录人工耗时，M2 再检验采集助手收益 |
| 可提取完整思考链并断言内部淘汰原因 | 删除 | 只处理可见内容及出处；诊断是证据支持的假设 |
| 固定 1.5 秒/3 秒代表所有 AI 抓取阈值 | 删除 | 呈现实际访问条件与正文缺失，不能推出引擎内部抓取结果 |
| 强制每段品牌名、结构化数据必增推荐 | 改成可读性建议 | 事实、清晰表达和授权来源优先；内容质量分不预测真实效果 |
| 写入数据库生成日志即完成隐式标识 | 纠正 | 文件输出需相应标识处理与可检查产物；参照 W04 |
| 共享平台整个域名可算品牌自有来源 | 纠正 | 需要账号或页面级归属；R-M0-06 |
| 全部客户统一 1+3 渠道 | 改成主页面+1 个证据支持的渠道起步 | 降低首轮投入；M1 再按信源缺口扩张 |
| 套餐价格及 60%–80% 毛利足以证明商业可行 | 改成待测模型 | 记录调用、编辑、采集、复核和交付工时，不承诺现价或毛利 |

## 4. 大陆产品入口能力矩阵

这里区分“监测哪里”与“内容发布哪里”。以下全部为候选，启用状态由真实验证决定。

| 候选消费者入口 | API 候选关系 | 首次产品处理 |
| --- | --- | --- |
| 豆包网页/App | 方舟为独立 API 观察对象 | 分开命名及报告，分别记录模式和引用完整性 |
| DeepSeek 网页/App | DeepSeek 模型接口不是其消费者搜索的证明 | 人工真实入口存证；自建搜索+模型另记 custom_pipeline |
| 腾讯元宝不同模型/模式 | 不将任一混元/DeepSeek API 等同元宝 | 入口+模式分别定义，公众号引用按实际页面归属 |
| Kimi 网页/App | Moonshot API 需独立验证 | 消费者入口与 API 不合并 |
| 百度 AI 搜索/文心产品 | 千帆接口需独立验证 | 搜索产品、聊天产品分别建条目 |
| 千问产品/夸克 | 百炼接口为 API 候选 | 不将千问、夸克及百炼合为一个平台 |
| 纳米、智谱等其他候选 | 未完成本轮核验 | 仅进待评估清单，不展示为已覆盖 |

M0 选择 1 个真实可用官方 API 与 1 个真实消费者入口，默认从 W02/W03 对应服务中验证 API 候选，但不强制供应商。消费者端允许人工流程，即使自动采样不能开通也能收集真实证据。两轨都保留联网条件未知状态；无法证明联网时不能进入联网合格指标。

能力台账每条包含：展示名称、观察对象、采样方式、可用条件、引用能力、联网可观察性、地区控制能力、验证时间、限制、停用原因。默认验证有效期 30 天；发生模式/协议变化立即降级待验证。这是产品默认值，不是外部平台保证。

## 5. 渠道选择与本土化

| 内容候选 | 产品内价值 | 首发可交付边界 |
| --- | --- | --- |
| 官网/自有公开页 | 可控事实原点、产品参数、适用边界、业务承接 | 指定页检查+修改建议+素材包；客户自行实施 |
| 微信公众号 | 自有品牌长文与案例承载候选 | 格式预览、素材导出、人工发布回填；草稿连接属于 M2 |
| 知乎 | 问题式解释、比较与专业回答候选 | 原创问题回答稿、来源清单、人工发布与页面归属 |
| 百家号/头条 | 图文指南与公众信息承载候选 | 渠道变体与声明核对，不承诺开放写接口 |
| 小红书/抖音/B站/视频号 | 消费和本地场景的后续内容候选 | M2 内容变体与授权可用性评估，不承诺全平台自动发布 |
| 垂直媒体/社区/行业资料站 | 独立第三方支持证据 | M1 来源研究与人工登记；不做付费媒体采购市场 |

选择排序：目标购买场景匹配 → 当前样本已出现的来源 → 品牌是否有合法可编辑页面 → 内容形式适配 → 制作/维护成本。没有引用证据仍可提出试验渠道，但必须显示“待验证假设”。不能只根据母公司关系推断推荐权重。

本土化字段包含中文品牌全称/简称/产品线/同名排除词、目标城市和服务范围、人民币价格的有效期、中文问题的购买阶段、平台账号归属。目标地区与实际采集地区分开；未知地区不能伪装成城市定位测试。

## 6. 功能方向及先后顺序

| 方向 | 可观察用户价值 | 首发/扩展 |
| --- | --- | --- |
| 购买问题地图 | 把咨询问题变成可跟踪资产，知道哪里缺内容 | M0 问题簇；M1 专业题集及覆盖 |
| 证据驱动下一步 | 每条建议说明证据、假设、修改目标和复测条件 | M0 |
| 品牌事实与纠错 | 发现 AI 错述、同名和跨渠道参数冲突，追踪更正 | M0 事实卡；M1 持续监测 |
| 引用来源网络 | 连接问题、答案、引用页、品牌/竞品，找到可执行缺口 | M1，基于已观察来源 |
| 持续内容维护 | 事实到期引发所有受影响稿件与线上页面更新 | M0 阻断；M1 维护工作台 |
| 有效咨询反馈 | 连接观察到的 AI 引荐、自报与销售确认，保留归因限制 | M1；M2 接入连接器 |
| 受控经营助理 | 聚合一周缺口、提出计划，逐项确认后执行 | M2，有动作预览和可撤销权限 |

## 7. 待验证假设与失败后的动作

| 假设 | 验证方法 | 通过目标/失败动作 |
| --- | --- | --- |
| 首发小 B 用户能自助开始 | 5 人可用性走查 | 见 Intent；失败就简化材料与问题预览 |
| 通道可产生可复查样本 | API 10 题×2 轮；消费者入口 3 题×2 轮，记录原文/模式/引用及费用 | 能解释来源与缺失；不能证明联网时只展示相应观察层，正式门禁阻塞 |
| 建议能被执行 | 3–5 品牌试点，记录补证、编辑、核验阻塞 | 至少 3 个完成闭环；不足则改建议/交接，而非增加稿量 |
| 外部渠道值得投入 | 选 1 个渠道，记录已有引用、内容动作和同口径复测 | 结果可正可负；负结果进入下一轮决策 |
| 采集助手值得做 | 记录两周人工采样耗时与失败 | 节省工时能覆盖维护成本才进入 M2 |
| 单品牌经济可持续 | 实际 API、生成、人工采集/编辑/审核/交付成本汇总 | 毛利目标由经营者试点前冻结；失败则降频/缩范围/调整服务 |

单位直接成本 = 调用与生成分析 + 存储与外部服务分摊 + 采集/编辑/审核/交付工时成本。M0 试用可不向用户收费，外部成本仍有硬上限。未知费用标待核对，不计零。无历史账单时不预填人民币单价。
