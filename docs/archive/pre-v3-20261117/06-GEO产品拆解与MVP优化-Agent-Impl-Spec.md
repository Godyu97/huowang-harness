# GeoPro 产品拆解与 MVP 优化 Agent Implementation Spec

> 版本：MVP-R2（Geomix 功能借鉴版）｜日期：2026-11-17（Asia/Singapore）  
> 用途：供产品、研发 agent、测试及试点交付共同执行的实现规格。  
> 结论：在 R1 证据闭环上，吸收 Geomix 的问题预览、资料录入、模板复用、逐篇任务控制和导出体验，形成 **购买问题 → 证据诊断 → 小批次内容计划 → 审核交付 → 发布核验 → 同口径复测**。  
> 本轮边界：仅优化产品功能、交互、业务规则及其验收合同；既有工程架构与技术选型保持不变，不参考 Geomix 的框架、组件库、存储、队列或模型选型。  
> 当前仓库是文档与报告门户，尚无 `apps/web`、Worker 或业务数据库实现。本报告是实现蓝图，不表示这些功能已开发或验证上线。

### 2.2 值得借鉴的体验

1. 任务入口直接：主词/品牌即可开始整理素材，避免一开始填写复杂技术配置。
2. 批处理具有上限：生成数、发布总量、每日量和去重策略都能表达运营约束。
3. 操作前提示费用：把用户即将执行的动作与费用联系起来。
4. 现有素材可复用：图库、知识库和提示词模板减少重复输入。
5. 报告可交付：业务人员容易找到数据大屏和诊断报告。

## 3. 优化后的 MVP 产品边界

### 3.1 首个客户与核心任务

**首个客群：同一 B2B 垂直行业、能提供真实产品资料且有官网或可用机构账号的 1–2 家品牌。** 由品牌负责人审批，1 名运营完成采样核验与交付；Agency 可以作为受限项目协作者，不先开发代理商商业门户。

核心用户任务：当客户在目标 AI 入口询问一个购买问题时，确认品牌是否被准确提及/推荐、发现缺失或错误信息，并通过一项可核验的内容改动完成后续复测。

业务目标是验证客户愿意为可解释诊断与执行闭环付费。软件验收不绑定“推荐率必涨”或“必有成交”。数据结果为零或无改善也必须如实交付。

## 4. 端到端业务合同

### 4.1 标准流程

1. **建档**：品牌管理员确认 CSP、目标产品入口、场景、可改页面、事实审批人、内容审批人及有效线索标准。未确认 CSP 可保存草稿，不启动正式实验。
2. **题集**：10 品类发现 + 10 场景方案 + 10 高意图约束 + 5 竞品比较 + 5 品牌事实；最多 10 探索题另表。运营导入/AI 生成候选后人工筛选、去重、确认来源。只有前 30 题进入自然推荐主指标。
3. **计划**：预览题数×通道×槽位×次数、预算上限及重试预算；冻结题文本、竞品集、地域、模式、搜索要求、时段和分析规范。监测提示不注入品牌私有知识库。
4. **基线**：连续 14 个自然日。API 与 C 端分别冻结样本和质量报告；C 端按预先排定日历执行。期间可准备草稿，不改实验目标内容。紧急事实纠错单独登记为干预并重建受影响基线。
5. **诊断**：每条建议必须带 `observation_id/citation_id/audit_finding_id` 之一。缺参数、事实错误、引用信源缺口分别生成任务；“没有被提及”本身不能证明品牌被模型淘汰。
6. **内容**：确认 Brief，选择批准且允许对外使用的事实版本；生成草稿及主张映射；阻断无来源数值/资质/案例。生成失败可恢复，不重复覆盖已编辑版本。
7. **审核与分发**：品牌管理员批准具体渠道版本；运营导出官网与单渠道素材包，在外部人工发布，回填公开 URL。审批不是模型评分通过的同义词。
8. **生效**：匿名访问与关键主张一致性核验通过记录 `effective_at`；平台限制访问时由两名有权限的不同用户核验并存证。草稿链接不得计入生效。
9. **复测**：按变更批次到期生成 D+7、D+14、D+28 报告；对比只用冻结共同题和匹配条件。继续优化/补证/观察/停止都应有依据。

### 4.2 AI 组件的输入输出与权限

| 组件 | 输入 | 必须返回 | 可执行动作 |
| --- | --- | --- | --- |
| 问题候选器 | 行业、真实需求摘要、场景 | `text, intent, source_ref, rationale` 候选数组 | 写候选草稿，不能冻结正式题集 |
| 回答分析器 | 单份不可信原文、实体词典、分析规则 | 提及/推荐/未知、证据字符区间、引用映射、置信与原因 | 返回 JSON；无发布、任意抓取或写库工具 |
| 诊断建议器 | 已复核分析、引用和审计项 | `finding_type, evidence_ids, hypothesis, action, acceptance` | 建议候选工单，不能把推断升级为事实 |
| 内容生成器 | 已确认 Brief、批准的对外事实版本 | 正文、`claim → fact_version_id`、未解决问题、生成元数据 | 保存待审草稿，不能审批或公开发布 |
| 报告解释器 | 服务器生成的统计 JSON | 简明解释、限制和后续建议 | 不计算/改写指标，不补造样本或线索 |

所有 AI 输出经过 schema 校验；输出引用的 ID 必须存在且属于本租户。证据区间必须对应原文，不能由模型自证。公开推理摘要仅称为“产品显示的解释”，不作为隐藏内部推理、真实因果过程或完整检索覆盖的证据。

## 5. 指标与实验合同

继承 `metrics-v2`，本次补充的实现规则版本标记为 `metrics-v2-r1`。数据库保留 `metrics_version`，旧快照不随新规则自动变化。

### 5.1 观测单位与分母

最小测量单位为冻结计划中的一个槽位：`plan_version + prompt_version + channel_config_version + scheduled_at + repeat_index`。同一槽位最多选定一个成功 observation 进入指标；重试与分析重跑不增大计划分母。补采属于新时间槽位，不能倒填历史。

| 符号/字段 | 定义 |
| --- | --- |
| P | 当前冻结窗口内计划槽位总数，含失败、错过与暂停槽位 |
| V | 有完整可用回答的槽位数；截断回答不自动算完整 |
| E | V 中满足该计划测量条件的回答；联网测量要求有实际搜索触发证据 |
| Jm | E 中品牌提及可判断的样本数，排除同名歧义 |
| Jr | E 中推荐关系可判断的样本数，排除语境不足/截断/歧义 |
| C | E 中原生引用列表完整可观察的样本数；完整空列表计入 C |
| M / R / O | 分别为确认提及、明确适合推荐、含至少一个自有原生引用的样本数 |

`E <= V <= P`，`Jm/Jr/C <= E`。样本入 E 的规则按 `measurement_protocol_version` 冻结。消费者端无法确认联网状态时记 `unknown`，可展示原文与探索观察，但不混入要求联网的正式 E；API 请求参数开启搜索本身不证明执行了搜索。

### 5.2 必须实现的指标

| 指标 | 计算与展示 | 边界规则 |
| --- | --- | --- |
| 采样质量 | `V/P`、`E/P`、`Jr/E`、`C/E`，配数量 | 分母为 0 显示 N/A；失败原因可下钻 |
| 单题提及/推荐率 | `M_q/Jm_q`、`R_q/Jr_q` | 分母为 0 为 null；明确未提及可判推荐为 false |
| 非品牌推荐率 | 固定共同非品牌题的单题推荐率等权均值 | 不按成功样本量加权，不混入品牌题或探索题 |
| 高意图推荐率 | 固定 A3 子集等权均值 | 同时展示题数和样本量；子集未覆盖不外推 |
| 自有引用率 | `O/C`，并列 `C/E` | 原生引用完整且空为 0；partial/unsupported 为不可完整判断，排除 C |
| SoV | 本品牌确认提及数 / 固定品牌集合各品牌确认提及数之和 | 仅用品牌集合均可判断的共同样本；每品牌每回答最多计 1；总和为 0 为 N/A |
| 品牌事实错误率 | 有已复核事实错误的回答数 / 已复核含品牌的回答数 | 未复核不进入分母；记录复核人和事实版本 |
| AI 关联有效线索 | 满足冻结标准并经销售确认的去重线索数 | AI referrer、专属落地入口、客户自报分别展示，不推算不可见流量 |

任何指标 DTO 必须含 `value: number|null`、`numerator/denominator`（均值另含 per-question 数组）、`sample_count`、`question_ids`、`coverage`、`status`、`reason_codes`、`metrics_version`、`analysis_version`、`snapshot_id`。API 与消费者端分面板；不同产品入口、模式、地域及证据类型不合成为“全网 AI 分数”。

### 5.3 前后对比规则

1. 比较键为 `prompt_version + evidence_type + channel_config_version + measurement_protocol_version + region + mode + time_band`。竞品集版本与分析规则必须一致。已观察到的模型版本变化记录为环境断点；模型版本未知明确显示 unknown。
2. API 默认按品牌时区固定时间带采样，单次实际执行时间保留。C 端记录网页/App 类型、会话是否新建、登录/个性化状态和可见模式；无法控制的条件在结论中声明。
3. 每个前后窗口需总体 `E/P >= 90%`，单题 `E_q/P_q >= 80%`。本报告另要求 `Jr/E >= 90%`、共同核心题保留率 `>=90%` 才给“可比”状态；这些是产品质量阈值，不代表统计显著性。
4. 共同题由预先冻结题集和条件一致性决定，不能依据结果好坏筛题。某题质量不达标或 Jr 为零时列入排除清单，保留原 P，显示保留率；不允许静默删题美化结果。
5. D+7、D+14、D+28 是报告检查点。基线为生效前已冻结的连续 14 日；检查点使用截至该点的最近 7 个自然日作为 API 观察窗。C 端采用同一 7 日窗内预定的 2 次采样，与基线末 7 日的预定 2 次比较。日期区间采用半开区间 `[start,end)`，时间带/工作日构成应匹配，否则标出日历差异。
6. 在冻结基线完成前不得将干预批次设为生效。一个批次涉及多个 URL 时，只有预定必需 URL 全部核验通过才以最后一个核验时间为 `effective_at`；部分完成应建独立批次，不回写原批次起点。
7. 变化用百分点 `after - before`；显示逐题原始样本、覆盖和排除项。P0 只提供描述性前后变化，不声称统计显著或因果归因；没有对照组时用“同期变化”。

### 5.4 手算 fixtures 与预期

| 用例 | 输入 | 必须输出 |
| --- | --- | --- |
| 零数据 | `P=0,V=0,E=0` | 所有比例 N/A；空图；无 100 或 12.5 占位数据 |
| 全失败 | `P=10,V=0,E=0` | `V/P=0%`、`E/P=0%`；推荐率 N/A，而非 0% |

## 7. API 与权限合同

### 7.1 公共约定

- 业务路径统一 `/api/v1`；同步创建返回 `201`，查询 `200`，异步任务返回 `202 {operationId,status,pollUrl}`。
- 所有可触发外部成本、生成快照或修改状态的 POST 要求 `Idempotency-Key`。作用域为 `tenant + actor + route + key`；相同 key/body 返回原结果，不重复执行；相同 key 不同 body 返回 `409 IDEMPOTENCY_CONFLICT`。持久记录至少覆盖任务生命周期及 30 天。
- 更新使用 `expectedRevision`；冲突返回 `409 REVISION_CONFLICT`。审批额外检查服务器重算的 hash 与事实 revision 集，不信任前端 hash。
- 会话失效 `401`，权限不足 `403`；不可见的对象统一 `404`，避免泄露存在性；schema 不合法 `422`，预算/依赖/状态冲突 `409`，限流 `429`。
- 统一错误体 `{code,message,fieldErrors?,operationId?,retryable,traceId}`。敏感内部错误只进入脱敏日志，前端不显示密钥、供应商原始报错内容。
- 所有列表游标分页，默认 20、最大 100；详情/导出/轮询/附件下载同样鉴权。撤销 grant 后轮询也不可读取原任务结果。

## 8. 状态机、队列与预算

### 8.1 采样与分析

```text
slot: scheduled -> queued -> running -> succeeded
                                |--> failed
                                |--> needs_reconciliation
      scheduled/queued -> paused_budget | missed | cancelled

analysis: pending -> running -> succeeded
                       |----> failed -> pending（只重跑分析）
```

`paused_budget` 可以在计划时窗内恢复；超过冻结时窗转 missed，不伪造原时刻采样。`cancelled` 保留在冻结 P 中并注明原因；下一个计划版本可停止新增槽位。`needs_reconciliation` 表示请求可能已到供应商但结果/费用不明，不能直接当作可安全重试的失败。

队列建议：`sample.collect`、`sample.analyze`、`site.audit`、`content.generate`、`publication.verify`、`report.snapshot`、`fact.expiry-scan`。Outbox 与业务事务原子提交，投递至少一次；handler 根据业务唯一键幂等。不能以消息队列声称端到端 exactly-once。

- 原始返回落私有对象存储，记录 hash 后再将 observation 标 ready。对象上传成功而 DB 失败时保留 pending manifest，恢复优先对账/补登记，不能再次付费采样。
- 外部调用之前持久化 attempt、request key、预算预留。供应商支持幂等/查单时恢复查询；不支持且网络超时不确定时隔离为待对账，允许人工结束该槽位，禁止盲重试。
- 明确未执行的限流/临时错误才自动退避，遵守 Retry-After；默认最多 2 次额外尝试，仍受预算/时窗约束。4xx 参数/权限错误直接停通道并给可操作原因。
- Worker 租约过期只说明本地执行者消失，不证明远端没有执行；恢复逻辑必须经过 attempt 状态判断。

### 8.2 内容与发布

```text
brief: draft -> confirmed -> invalidated（事实/目标改变）
content approval: draft -> in_review -> approved | rejected
                  approved -> invalidated（正文、素材、事实变更/过期/撤销）
publication remote: not_started -> exported -> reported_public
verification: pending -> verified_public | content_mismatch | access_limited
              access_limited -> manually_verified_public（两人存证）
maintenance: active -> needs_review（线上内容变动/事实过期/URL失效）
```

P0 的 `reported_public` 是运营声明，不等于验证通过。`effective_at` 只能由核验用例写入；采用服务器首次核验通过时间，用户填的发布时间作为单独信息不替代它。两人核验第二次通过时才生效。

事实有效性在生成、提交审核、批准、导出、回填、核验每个节点重新检查；不能仅依赖定时过期任务。对已上线但后续失效的事实，生成维护任务、标记实验干扰，不自动修改外站或删除历史报告。线上排版差异不直接算失败，核验标题、品牌实体、关键主张和值；无法自动确定一致时转人工。

### 8.3 配额与供应商成本

预算在数据库短事务内锁定预算行：`settled + reserved + new_upper_bound <= cap` 才创建 reservation 和 outbox。供应商单次费用上界应来自冻结价格版本与 token/search 次数硬限制，不能把均价当上界。通道无法限制最大暴露成本时，不允许启用自动调度；先在受控 PoC 中确认成本边界。

每个 attempt 记录实际成本/估算/未知状态。已成功任务客户端重发同幂等请求不新增配额扣减；供应商真实重试成本仍计入 `provider_usage_event`。未知费用保留预留、暂停继续支出或人工对账，不自动按零结算。月结通过供应商账单补差，保留估算与实际差异。

成本预览必须列出“预计调用、最大尝试、已预留、可用余额、成本是否估算”。客户看到的套餐配额、执行次数与供应商费用分别显示，不能把参考产品的点数直接映射成 API 成本。

## 9. 证据、内容包与报告格式

### 9.1 手动消费者端存证

P0 提供今日待采题单、复制问句、上传/粘贴回答、粘贴引用、截图预览和确认提交。每条绑定指定槽位和题版本；系统保留实际观察时间、提交时间、采集者、产品入口、会话条件与 `capture_method=manual`。不把用户上传截图称为不可伪造证明；界面标记“人工采集”，允许复核抽检。

截图仅保留所需回答区域，上传前可预览并提示遮盖个人信息；不收集 Cookie、密码、历史会话全量数据。缺失原文或条件不明时仍可存证，但质量状态单独标记，不自动进入正式指标。

### 9.2 素材包

```text
publication-pack/
  manifest.json             包版本、变体 hash、审批、事实 revision、生成标识
  article.md                可编辑文本
  article.html              清洗后 HTML，官网或选定渠道变体
  claims.json               主张与已批准事实版本映射
  assets/                   经授权的品牌图片（如有）
  publish-checklist.html    渠道声明、账号、链接回填和核验说明
  site-patch.json            仅官网包：title/description/结构化数据建议
```

`manifest.json` 包含 `schema_version, brand_id, variant_id, content_hash, approval_id, fact_version_ids, target_channel, generated_at, ai_assisted, model_ref, labeling_profile_version`。面向外部的素材包剔除内部注释、私密事实附件、供应商密钥和客户无关数据。图片不是硬性要求，无图不阻断纯文本 FAQ 生成。

结构校验分为硬门禁和建议项：事实失效、无来源核心主张、未获准公开事实、缺有效审批属于硬门禁；摘要长度、段落长度、标题形式和表格建议只作可解释提示，不用任意“AI 友好分”保证被引用。避免强制每段重复品牌名造成关键词堆砌。

### 9.3 报告快照

报告依次展示：目标/观察区间 → 执行成果 → 数据质量 → API 趋势 → C 端观察 → 引用与事实错误 → 同口径前后变化 → 线索证据 → 限制/环境变化 → 下轮行动。正文附关键样本链接，全部统计附可复算 JSON。

快照 manifest 锁定：题集/计划/通道/协议/分析版本、纳入 observation IDs、排除原因、逐题分子分母、基线/观察窗口、干预批次、内容 hash、费用口径和生成代码版本。HTML 与 JSON 使用同一快照，禁止前端临时再算一套图表。

默认只对已授权成员开放；P0 不做任何持令牌即可访问的匿名分享链接。下载为真实 HTML/JSON 文件，HTML 使用打印 CSS 支持人工另存 PDF；原始客户私密附件不内嵌到导出中。修正错误需要新快照，旧快照显示已被新版本取代。

## 10. 安全、运行质量与外部能力验证

### 10.1 必须实现的技术护栏

- 安全抓取：只允许 HTTP/HTTPS 和规定端口；解析并校验 IPv4/IPv6、IPv4-mapped 地址及每次重定向；拦截 loopback、private、link-local、reserved 和云元数据目标；连接层绑定已校验目标防 DNS rebinding。限制 5MB、10 秒、最多 3 跳，不携带用户 Cookie/Authorization。解析 HTML 禁止执行脚本。
- 站点检查：只检查用户登记的站点及最多 5 个指定 URL；首版检查 HTTP 状态、正文可读取、title/canonical/robots 和主要事实是否在文本中。单次响应慢不能断言某 AI 一定抓不到；测量耗时带执行地域和时间。
- 不可信内容：网页、回答、附件和模型输出均按数据处理；输出 HTML 清洗，拒绝脚本与危险 URL。分析器无执行工具；外部文本中的指令不能改预算、授权或发布状态。
- 对象存储：私有、租户范围、短期上传、类型/大小校验；上传 HTML/原始快照只作为附件下载，不同源执行；业务删除经授权和保留策略执行，防止报告链条无提示失效。
- 日志与审计：trace 覆盖 operation/slot/attempt，不记录密钥、Cookie 或客户完整私密事实；审批、授权、导出、纠错、对账均有 actor 与时间。
- 成本保护：每通道并发初始 2、每品牌并发 1，实际值由 PoC 调整；429 自动限流。单通道异常率持续超过预设阈值触发暂停，新启用须记录原因。

### 10.2 PoC 能力台账

官方文档只能确定接口存在，不能证明当前账号已开通。当前公开文档中，百炼不同协议的联网开启方式不同；方舟也区分搜索工具与组件开通条件。实现时必须按协议、模型和账号逐项记录，不能只设一个 `enableSearch=true` 就宣称通过。来源：[阿里云百炼联网搜索](https://help.aliyun.com/zh/model-studio/web-search)、[火山方舟联网搜索工具](https://docs.volcengine.com/docs/ark/web-search?lang=zh)，本次查阅日期 2026-11-17。

| 验证项 | 原始证据 | G0 通过标准 | 不通过时 |
| --- | --- | --- | --- |
| 官方 API | 协议、模型版本、20 道题至少 2 轮、响应/引用/搜索事件、费用 | 至少 1 通道取得可解释回答、可判断联网、可观察原生引用与可限制费用上界 | 未通过不得启动正式联网指标；调整通道并保留失败记录 |
| 引用真实性 | 角标/引用字段到回答的关联、空引用、partial、搜索候选 | 不把所有搜索结果算作已引用；至少覆盖有引用和空/不可观察路径 | 标记 partial/unsupported，缩小指标承诺 |
| C 端入口 | 10 固定题×2 轮、原文/截图/模式/耗时 | 有可重复的人工采集 SOP，条件和搜索状态可以标记 | 可保留探索观察；正式消费者端联网结论延期 |
| 渠道选择 | 客户受众、账号可用性、实采引用域名/URL | 从公众号/知乎/百家号/头条等候选中选 1 个；记录理由 | 先只交付官网，外部渠道目标标阻塞而非虚构完成 |
| 单页核验 | 公开页、草稿页、需登录页、正文不匹配页 fixtures | 状态区分正确，受限页转人工 | 禁止把可访问响应码等同于公开且一致 |
| 单位经济 | 实际调用费用、运营工时、生成修订工时 | 得到试点单品牌成本范围和最大预算 | 调低采样规模或调整报价，不沿用纸面毛利 |

项目旧调研中“某入口偏好某平台”“15 分钟完成多平台采集”“固定抓取超时范围”“零封号风险”“100% 合规”等表述不作为本报告的事实前提。保留前两类可测假设；平台规则、账户资格和维护成本在接入前验证。AI 内容标识需覆盖适用场景的显式提示与文件元数据，**数据库里的生成日志不能代替文件隐式标识**；`manifest` 仅承担审计，具体格式由实现时的标识 profile 和适用标准验收。依据：[生成合成内容标识办法第 3–5、10–11 条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。

### 10.3 运行目标

这是待测试的验收目标，不是当前性能声明：在 2 品牌、每品牌 40 核心题、单 API 日采、10 名并发用户的试点配置下，普通 API P95 < 1 秒（不含外部模型调用），异步登记 < 2 秒，任务进度在 10 秒内可见。软件调度需通过 72 小时故障注入；外部调用延迟按实测呈现，不承诺 1 秒出诊断。

基础门禁：API 槽位 `V/P >=95%`，正式实验 `E/P >=90%`；低于门禁可以展示异常与探索报告，不能隐藏失败后宣布完成正式评估。备份恢复目标沿用基线 `RPO<=24h, RTO<=4h`，须有实际演练记录。

## 13. 排期、成本与扩展门槛

### 13.1 工程容量估算

| A00 PoC/契约 | 4 |
| A01 租户/工程底座 | 8 |
| A02 事实/题集 | 7 |
| A03 采集/队列/预算 | 10 |

### 13.2 可复算的首版采样预算

默认单品牌：40 核心题 × 1 API × 每日 1 次 × 30 日 = **1,200 个计划槽位/月**；探索题 10×每周一次×4 次 = **40 次**；另预留 10% 调用余量，预算模型共 **1,364 次**。探索与重试余量属于成本估算，不进入核心指标 P。最大 2 次额外尝试由硬预算约束，不表示保证每槽位都有两次免费重试。

仅作敏感性计算，若平均每次综合费用假设为 ¥0.05 / ¥0.10 / ¥0.25，则联网采样约为 **¥68.20 / ¥136.40 / ¥341.00 每品牌每月**。这些不是供应商现价，也不含内容生成、语义分析、存储、服务器、人工和税费；PoC 应用真实响应及账单替换假设。

C 端每品牌 10 题 × 每周 2 次 × 4 周 = **80 条/月**。若单条端到端人工耗时为 2/4/6 分钟，则仅采集约 **2.7/5.3/8 小时/月**，另加审核、返工和报告。原报告中的快速采集估计不能用于未完成的插件或无计时证据的交付报价。

`单品牌直接成本 = API + 分析/生成 + 存储/云分摊 + 采集/编辑/复核工时成本`。`直接毛利率=(收入-直接成本)/收入`。首轮报告展示实际工时；软件与代运营收入成本分开，不用“自动化”字样隐藏人工工作。

### 13.3 P1 触发条件

- 单站采集助手：连续两周人工存证耗时成为主要成本，预估每月节约工时足以覆盖开发维护，且允许的采集流程经过核验。
- 第二 API/第二渠道：试点发现明确未覆盖购买场景，或引用数据证明增加渠道有检验价值；同时增加质量和费用预算。
- 草稿/CMS 连接器：客户账号权限真实可用，人工发布反复耗时；先支持草稿与对账，公开动作单独授权。
- Agency 经营能力：至少 3 家持续使用客户，品牌授权/交付模式稳定，实际毛利达到团队冻结的目标后扩展。

## 14. 结论与首个可演示切片

MVP-R1 保留参考产品“简单建档、任务化批量操作、费用透明、报告易交付”的优势，将成功标准设为：**每条诊断能回到证据，每篇稿件能回到事实，每次发布能核验，每个变化能复算。**

首个可演示切片以一个合成品牌贯穿：创建品牌和两个角色 → 录入并审批事实 → 冻结题集 → 采集并保存证据 → 从一条有证据缺口生成任务 → 创建/审核稿件 → 导出素材包 → 对测试公开页核验 → 用明确标记的历史 fixture 演示复测报告。真实试点必须另外经历 14 日基线与实际到期窗口，演示数据不能冒充效果证据。

尚待验证的外部依赖集中在 A00：实际可用 API 账号与费用、消费者入口采集条件、客户可改页面/渠道、人工耗时及标识落地方式。这些不阻止编码 agent 按契约完成本地实现，但在对应门禁通过前不能宣称正式数据或业务效果已验收。
