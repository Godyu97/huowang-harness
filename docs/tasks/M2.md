# M2 开发任务

> v3.0｜全部待实施；文档完成不代表业务任务完成。只做依赖满足的任务；默认当前开发级别为 M0。可拆成更小改动，但 ID、验收和跨级依赖必须保留。

先读 [入口](../README.md)、[公共合同](../04-产品功能规格-SPEC.md)、[指标合同](../07-指标与证据合同.md)。依赖指功能合同可复用且验收完成；本地可用显式 fixture 开发，真实门禁不能用 fixture 替代。跨级任务还须满足上一阶段 GATE。

每项交付包括用户行为、数据版本/状态、权限、失败处理、实际验证与运行说明。不以空接口标完成，不由本文反推技术栈。

## [ ] T-M2-01 消费者入口辅助采集

- 级别/需求：M2 / R-M2-01。
- 规格：[S-M2-01](../specs/M2.md#s-m2-01)。
- 依赖：T-M1-01、T-M1-08。
- 输入准备：允许的目标入口、冻结题单、用户已打开的页面、明确采集动作和证据权限。
- 交付边界：至少一个已核验入口的辅助流程、证据预览、质量与耗时记录、退化到人工。

实施步骤：
1. 将规格中的输入、产物与状态实现为可运行行为，保持公共对象 ID 与版本语义。
2. 完成“监测 → 今日采集清单/采集助手”正常路径，以及本规格列出的异常/恢复入口。
3. 执行 AC-M2-01-1、AC-M2-01-2、AC-M2-01-3，保留输入、预期和实际结果，不只提供构建成功截图。
4. 对依赖功能做必要回归；涉及真实外部能力时记录来源/时间/权限/费用，或明确未验证。

完成证据：消费者观察、采集质量清单、人工耗时对比。，以及对应验收记录。仅实现该项增量，不重新定义 M0 口径。
