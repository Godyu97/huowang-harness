## S-M1-01 持续监测与质量异常提醒

- 需求：R-M1-01；任务：[T-M1-01](../tasks/M1.md#t-m1-01)。
- 用户价值：让品牌每周知道哪里发生了值得处理的变化。
- 操作者：负责人、分析者。
- 入口：监测 → 计划/提醒。
- 输入：冻结题集、通道、频率、时段、月预算、提醒阈值、接收成员。

1. 默认核心题每日 1 次、探索题每周 1 次；消费者人工样本默认每周两次指定题单，不宣称自动采集。
2. 暂停只影响未来槽位，历史失败仍保留；预算调整建立计划版本，不删除失败以美化覆盖率。
3. 先报质量异常再报业务变化：覆盖不足、引用字段变化、模式变更触发数据提醒；同条件推荐率连续两个已完成窗口下降超过阈值才生成趋势提醒。默认阈值 10pp，可在计划冻结前修改。
4. 相同品牌/类型/窗口合并提醒；状态 open/acknowledged/resolved/snoozed，恢复时补充记录；M1 只站内，不主动向外部群发送。

**输出**：持续采样计划、到期人工题单、站内提醒、预算预测。

**状态与合法变化**：plan draft → active ↔ paused → ended；alert open → acknowledged/resolved/snoozed。

**异常与恢复**：能力过期自动暂停相关通道，其他通道不受影响；不能自动替换平台；累计待核对费用占用预算。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-01-1 | 计划日采中出现预算不足 | 到达下一时段 | 暂停未执行单元并提醒，过去失败槽位仍在覆盖分母 |
| AC-M1-01-2 | 推荐率下降但覆盖严重不足 | 生成提醒 | 优先提示数据质量，不能宣称品牌表现确定下滑 |
| AC-M1-01-3 | 相同窗口重复触发告警 | 查看站内通知 | 合并一条并保留发生记录，可确认或稍后处理 |

## S-M1-02 竞品与引用来源机会分析

- 需求：R-M1-02；任务：[T-M1-02](../tasks/M1.md#t-m1-02)。
- 用户价值：识别竞争缺口，决定下一份内容应解决什么。
- 操作者：分析者、内容运营。
- 入口：AI 回答 → 竞品/来源。
- 输入：固定竞品集（0–5 个）、已观察引用 URL、页面归属、正文可得性、问题簇和时间范围。

1. 建立问题→回答→引用页→域名/账号→品牌/竞品的可下钻关系；只纳入已观察关系。域名聚合与具体页面清单同时提供。
2. 竞品使用相同实体消歧规则，份额基于固定竞品集及共同可判断样本。竞品集变更分段，零总提及为 N/A。
3. 原生引用存在、页面支持品牌、支持的是哪个主张分别判断；页面不可读时支持性未知。不能把引用某域名解释为平台永久偏好。
4. 仅明确有序推荐输出位置分布、上榜率及条件平均位置；缺席不记 0 或队尾。无序罗列不显示排名。
5. 来源研究可生成独立 Brief：写出议题缺口、可用事实和原创角度，不抓摘要冒充全文，不把他人品牌替换成自家品牌。

**输出**：可复查来源图/表、竞品份额、问题簇机会、带证据研究 Brief。

**状态与合法变化**：source observed → resolved/limited/unknown；opportunity proposed → accepted/dismissed。

**异常与恢复**：页面失效保留曾被引用证据；无法确认作者/账号归属归 unknown；不凭模型猜链接。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-02-1 | 同一回答反复提甲且同时提乙 | 计算份额 | 每品牌每回答最多计一次，固定竞品集和分母可见 |
| AC-M1-02-2 | 引用页受限 | 查看第三方支持 | 引用存在仍可展示，支持性为 unknown 而非正向 |
| AC-M1-02-3 | AI 无序列出品牌 | 查看竞品面板 | 不生成虚假排名；机会 Brief 保留来源且不复制品牌替换文案 |

## S-M1-03 品牌实体准确性与事实纠错

- 需求：R-M1-03；任务：[T-M1-03](../tasks/M1.md#t-m1-03)。
- 用户价值：管理同名、产品线混淆和过时品牌描述。
- 操作者：负责人、分析者。
- 入口：品牌资料 → AI 描述与纠错。
- 输入：实体别名/排除规则、产品线与服务范围、品牌核验题、已批准事实、回答主张。

1. 对品牌核验题提取可核对主张，逐条与事实版本比对，区分一致/冲突/缺证据/不适用；语义差异不直接认定错误。
2. “事实错误率”仅在人工复核样本集合计算，显示复核覆盖和抽样方法；品牌问题不混入自然发现推荐率。
3. 同名纠错可提出新的消歧规则；历史分析按新规则另生成版本，报告不静默回写。
4. 错误事件关联受影响问题、内容页和修正动作；修正官网不等于消费者答案已改，独立等待复测。

**输出**：品牌叙述清单、冲突主张、人工复核记录、纠错任务。

**状态与合法变化**：detected → needs_review → confirmed_error/not_error/insufficient → actioned → retested。

**异常与恢复**：过期事实不能判新回答错误；两份事实冲突先补证；未知不强行归负面舆情。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-03-1 | 回答使用与品牌同名的另一公司 | 人工确认实体混淆 | 保留证据并生成消歧修订，不算目标品牌自然提及 |
| AC-M1-03-2 | 只复核了 10/50 条且 2 条确认错误 | 查看事实错误率 | 显示 2/10 和复核覆盖 10/50，不写全体错误率 4% |
| AC-M1-03-3 | 官网已更正但复测仍错误 | 查看纠错状态 | 动作已完成、效果未解决分别显示 |

## S-M1-04 资料、素材与模板资产复用

- 需求：R-M1-04；任务：[T-M1-04](../tasks/M1.md#t-m1-04)。
- 用户价值：减少重复输入，让团队基于同一事实创作。
- 操作者：内容运营、负责人。
- 入口：品牌资料 → 资料/素材；内容 → 模板。
- 输入：文本、文档或公开资料 URL、图片及使用权；分类标签、版本、来源页码/片段；模板目的与输入槽位。

1. M1 支持可提取文本的常用文档导入，单文件默认 10MB/50,000 字，最多 10 个/批；扫描件或加密文件提示不支持，不制造抽取结果。
2. 抽取事实候选必须链接原片段与页码（可得时）；不能因资料进入库就视为批准。新增资料显示与批准事实的潜在冲突。
3. 图片可按用途/权利/到期检索；引用素材时固定版本。素材撤销通知依赖内容，不能直接删掉已发布链路。
4. 三类系统模板只读，可克隆为个人/团队模板；预览输入输出和适用场景；自定义模板不能关掉事实、公开许可和审核门禁。

**输出**：可追溯资料库、素材引用、模板版本与候选事实。

**状态与合法变化**：upload → extracting → ready/partial/unsupported/failed；素材 active/expired/revoked；模板 draft/published/retired。

**异常与恢复**：批量失败按文件保留原因，成功文件不重传；敏感资料默认仅工作区授权成员可读。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-04-1 | 文档有部分不可识别页面 | 导入 | 可识别部分保留，缺失标记并提示人工处理，不假造页码 |
| AC-M1-04-2 | 图片使用权被撤销 | 检查内容关联 | 列出引用版本和维护待办，历史记录仍在 |
| AC-M1-04-3 | 自定义模板要求编造客户案例 | 尝试生成和导出 | 不能绕过事实与审批门禁 |

## S-M1-05 多渠道变体与内容维护

- 需求：R-M1-05；任务：[T-M1-05](../tasks/M1.md#t-m1-05)。
- 用户价值：按渠道交付同一可信事实，并持续修复过时内容。
- 操作者：内容运营、审核者。
- 入口：内容 → 渠道日历/维护。
- 输入：主稿、已确认目标渠道/账号、版式规则、事实版本、维护周期、内容发布时间。

1. 从 M0 单外部渠道扩展至多个经确认渠道；每个变体独立正文、标题、批准、标识和发布状态，不以主稿批准自动放行全部变体。
2. 主页面优先更新；公众号/知乎/百家号/头条模板按内容特征适配，约束来自可更新 profile，不写死平台字数为永久规则。
3. 提供 Markdown/HTML 及可编辑文档包；无授权连接时仍采用用户人工发布和核验。
4. 事实过期、页面撤下、线上改写触发维护任务；按事实→稿件→渠道版本列影响面，避免逐页查找。重复触发合并任务。
5. 内容计划日历分别显示计划交付、实际公开核验、复测到期；不把计划日期当上线日期。

**输出**：渠道变体、批量交付、维护队列与内容日历。

**状态与合法变化**：沿用 M0 逐变体审批与发布状态；维护 open → assigned → repaired → reverified/blocked。

**异常与恢复**：部分渠道失败不回滚已核验渠道；新版事实未批准先暂停相关交付；导出不静默丢失表格。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-05-1 | 主稿已审，知乎变体改了价格 | 导出变体 | 独立重审，不能继承主稿批准 |
| AC-M1-05-2 | 同一价格事实关联 5 个线上页 | 事实到期 | 列出 5 页受影响，生成去重维护任务 |
| AC-M1-05-3 | 3 个渠道中 1 个发布受限 | 看内容日历 | 2 个核验结果保留，受限渠道独立标阻塞 |

## S-M1-06 专业题集、基线与正式阶段复测

- 需求：R-M1-06；任务：[T-M1-06](../tasks/M1.md#t-m1-06)。
- 用户价值：从快测升级为可审查的持续效果评估。
- 操作者：分析者、负责人。
- 入口：复测与报告 → 观察计划。
- 输入：客户成功计划、40 核心题（30 非品牌+5 比较+5 事实）和 10 探索题模板、采样协议、目标指标、干预批次、窗口、停止条件。

1. 40+10 是默认模板，可在采样前调整并冻结；核心/探索分开。默认 14 天基线；内容可准备，正式基线期间不得实施登记的干预。
2. 以每批所有指定页面首次核验完成时间的最大值为批次生效点。D+7/14/28 是累计观察检查点：从生效次日起取 7/14/28 个完整品牌时区日。基线为生效日前最近 14 个完整日，若不满足未干预条件重新建立。
3. 正式对比须双方总体 E/P≥90%、每题每窗 E_q/P_q≥80%、共同非品牌题≥冻结集 80%，并满足指标可判断门槛（见 07）。未达门槛输出探索，不隐去坏数据。
4. 预注册对照问题簇或未改动页是可选增强；默认前后变化仍称观察，不能用对照标签冒充因果试验。模型/营销/价格变化记录混杂因素。
5. 只在窗口实际到期后生成相应结论；工期完成不等于 D+28 观察完成。允许提前停止并给原因，停止后不抹去历史槽位。

**输出**：冻结 CSP、正式观察计划、批次基线、D+7/14/28 快照与决策。

**状态与合法变化**：draft → registered → baseline_collecting → ready_for_intervention → observing → checkpoint_due → reviewed/completed/stopped。

**异常与恢复**：发布延迟自动顺延，基线不合条件则阻塞；通道变化拆新阶段；不因效果不好事后改阈值。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-06-1 | D+14 尚未到期 | 生成 D+14 正式报告 | 只给进度，不产完整观察结论 |
| AC-M1-06-2 | 30 题仅 23 题可比 | 执行正式对比 | 低于 80% 门槛，标探索并列 7 题排除原因 |
| AC-M1-06-3 | 批次 3 页分别不同时间核验 | 计算生效点 | 使用最后一页核验时间，未核验则批次未生效 |

## S-M1-07 业务反馈与可观察线索

- 需求：R-M1-07；任务：[T-M1-07](../tasks/M1.md#t-m1-07)。
- 用户价值：把 AI 关联咨询带回优化决策。
- 操作者：市场运营、销售反馈者。
- 入口：复测与报告 → 业务反馈。
- 输入：手动或 CSV 导入的聚合访问/咨询记录、明确事件 ID、来源证据、有效性规则、跟进结果；默认不导入手机号等直接身份信息。

1. 区分可识别 AI 引荐、用户自报 AI、专属落地页相关、未知来源；同一咨询可保留多条证据但人数去重只计一次。
2. 来源汇总独占主分类优先序：可识别引荐 > 自报 AI > 专属页相关 > 未知；同时保留证据标签。专属页出现不等同 AI 因果引荐。
3. 有效咨询规则在统计前冻结，例如真实需求+目标行业+可跟进；后续修订有版本。原始咨询、有效咨询、成交各自显示。
4. 聚合流量允许缺 referrer，显示未知；只在会话/窗口/事件规则完整时算可识别 AI 引荐转化率。不得把人工自报咨询除以全部站点访问作转化率。
5. 官网日志/爬虫汇总与回答引用独立；首版只接受授权、脱敏的最小字段，缺少可用识别键时不猜去重。

**输出**：去重线索台账、来源强度、有效性反馈、报告业务层与下轮问题建议。

**状态与合法变化**：received → needs_dedup → qualified/disqualified/unknown → followed_up；修订保留版本。

**异常与恢复**：重复/字段缺失逐行报告；同 ID 冲突待复核；无法授权的数据不导入。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-07-1 | 同一咨询既有引荐又有自报 | 导入两行相同事件 ID | 咨询计 1，两个证据保留，主分类为可识别引荐 |
| AC-M1-07-2 | 没有可靠会话分母 | 查看转化 | 显示计数和 N/A 转化率，不造分母 |
| AC-M1-07-3 | 页面有爬虫访问但没有 AI 回答引用 | 查看报告 | 仅展示访问观察，不称被 AI 收录或推荐 |

<a id="s-m1-08"></a>
## S-M1-08 团队品牌权限与职责分离

- 需求：R-M1-08；任务：[T-M1-08](../tasks/M1.md#t-m1-08)。
- 用户价值：让运营、审核与负责人协作而不越权。
- 操作者：工作区负责人、运营、分析者、审核者、只读成员。
- 入口：设置 → 团队/品牌授权。
- 输入：成员身份、品牌范围、角色、授权有效期、审核策略。

1. 角色权限见 PRD；成员需角色与品牌授权同时满足。只读访问不获得附件导出或内部材料权限，导出单独授权。
2. 组织可启用双人审核：作者不能批准本人内容；事实批准与内容批准分别授权。启用后只影响未来交付，历史单人记录保留标签。
3. 撤销/到期立即阻止新的读取、下载和写操作；排队的授权动作执行前再检查，在途外部动作转待对账，不假称已撤回。
4. 多品牌切换保留各自上下文，搜索、批量导出、报告不能混入其他品牌；成员邀请不暴露私密品牌名。
5. M1 为组织内部协作，外部代理商委托与商业结算属于 M2。

**输出**：成员授权、角色矩阵、审批职责、访问与撤销记录。

**状态与合法变化**：invited → active → expired/revoked；审核策略版本化。

**异常与恢复**：最后一个负责人不能直接退出，先转移；邀请过期可重发；失去权限显示资源不可用。

| 验收 ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-M1-08-1 | 运营作者提交自己稿件且启用双人审核 | 尝试批准 | 拒绝，审核者可审，系统记录职责分离 |
| AC-M1-08-2 | 已排队任务的授权被撤销 | 任务执行/下载 | 重新校验并停止未执行动作，附件不可继续获取 |
| AC-M1-08-3 | 成员只获品牌 A 权限 | 切换到品牌 B 或批量导出 | 拒绝且无品牌 B 数据泄露 |
