# GeoPro 产品开发文档包

> 版本：3.0｜2026-11-17｜范围：产品功能与业务合同｜状态：可作为新项目开发输入，外部能力与商业假设仍须验证。

本目录可独立复制到一个新项目。当前实施范围是 **M0**；M1、M2 为已拆解的后续产品增量，不因为出现在文档中就默认同时开发。本文档包不指定编程语言、框架、数据库、组件库、任务系统、模型供应商或部署平台。

## 阅读与执行顺序

1. [产品 Intent](00-PRODUCT-INTENT.md)：服务谁、解决什么问题、成功如何判断。
2. [新旧功能评审](01-项目立项与方案审查总览.md)：两份原型及旧设计的保留、改造、后置与删除。
3. [PRD](02-产品需求文档-PRD.md)：用户旅程、页面、角色、全部分级需求与范围默认值。
4. [大陆 GEO 调研与决策](03-中国大陆GEO可行性调研报告.md)：证据强度、外部依据、差异化方向与待验证假设。
5. [公共功能 SPEC](04-产品功能规格-SPEC.md) 和 [指标与证据合同](07-指标与证据合同.md)：所有级别必须遵守的业务语义。
6. 按级别阅读 [M0 SPEC](specs/M0.md)、[M1 SPEC](specs/M1.md)、[M2 SPEC](specs/M2.md)，再执行相应 [M0 TASKS](tasks/M0.md)、[M1 TASKS](tasks/M1.md)、[M2 TASKS](tasks/M2.md)。
7. [验收计划](05-里程碑与验收计划.md)、[需求追溯矩阵](06-需求追溯矩阵.md)、[验收场景与样例](08-验收场景与样例.md) 用于交付检查。

## 优先级及完成定义

| 级别 | 用户价值 | 交付标准 |
| --- | --- | --- |
| M0 | 单品牌自助完成一次有真实证据的诊断、内容交付、发布核验和复测 | 闭环可用；真实渠道门禁通过；不能只交付页面或模拟结果 |
| M1 | 团队持续经营，覆盖更多问题、入口、信源和内容更新 | 可重复运营、同口径评估、协作及线索反馈可用 |
| M2 | 代理商规模交付、授权连接与受控智能协助 | 可授权、可撤销、可对账、有成本与质量边界 |

`M0/M1/M2` 是产品交付级别，不是原型旧任务的工程阶段编号。旧 P0/P1/P2、M0–M4、A00–A10、PF01–PF07 和 8/10 周排期均不再作为执行规则。

## 给 coding agent 的启动指令

```text
读取 docs/README.md、00-PRODUCT-INTENT.md、02 PRD、04 SPEC、07 指标合同。
当前只实施 docs/tasks/M0.md 中依赖已满足的首个未完成任务。
再读取该任务指向的规格及验收，不从历史原型恢复已删除的需求。
技术实现由新项目自行决定；先记录最小必要的实现决定，再开发。
交付用户可观察行为、边界处理、实际验证结果和未验证外部能力。
没有真实渠道时可完成本地契约与明确标注的演示，但不可标记 M0 上线验收通过。
不要将“修改已完成”“公开核验通过”“复测完成”“观察改善”合并为一个成功状态。
```

## 文件权威性

Intent 决定方向；PRD 决定范围；SPEC/指标合同决定精确行为；任务引用这些合同；验收不得私自改变口径。如发现互相矛盾，记录具体 ID 并修正文档，不能选择最容易实现的一种解释。`product-map.json` 是全部需求、规格、任务、依赖和验收的机器可读索引，与 Markdown 一起维护。

仅当前文档及 `specs/`、`tasks/`、`fixtures/`、`product-map.json` 属于执行基线。`archive/` 为原文快照，不参与开发。三个保留旧文件名的入口仅用于旧链接兼容。根目录旧 HTML 门户及原型不是本版需求源。

本次只整理设计和开发输入，没有运行原型业务链路，没有证明任何消费者平台已接通、内容已发布或效果已提升。自包含指核心行为与样例已写入本文档包，不包含真实密钥、账户授权、客户材料和第三方 SDK。

文档检查：`python docs/tools/validate_docs.py`（仅标准库）。它检查链接、需求映射、依赖与机器样例，不代表业务实现已通过验收。
