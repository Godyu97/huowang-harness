# Geo pro 需求梳理与效果导向修改建议

日期：2026-11-13｜性质：产品评审与修订提案｜评审基线：本地 v1.2 产品方案、metrics-v1 及配套实施文档。

**建议将 Geo pro 定位为面向品牌与代运营团队的 GEO 内容运营与效果验证平台。核心交付是：找出值得争取的客户购买问题，补齐能支撑品牌入选的真实内容，选择有依据的发布渠道，再用目标 AI 产品中的表现与业务线索决定下一轮投入。**

现有方案已经具备监测、事实审核、发布、复测和归因的完整骨架。当前最值得投入的是把客户目标、内容策略和复盘决策做具体。业务目标暂建议采用“可观察的 AI 关联有效咨询与销售线索”，推荐与引用作为前置信号；若客户主要购买品牌认知，则在项目开始时明确采用可见性目标。行业、目标产品和具体达标数值仍需在客户项目中冻结。

## 一 现有需求与主要修改判断

| 现有设计 | 判断 | 建议调整 |
| --- | --- | --- |
| API、消费者端、搜索候选分开记录；提及、推荐、引用分开计算 | 保留，是效果可信的基础 | 客户选择的真实 AI 产品必须成为相应成效目标的验证对象；API 趋势继续单列 |
| 40 道核心题、14 天基线、D+7/14/28 观察 | 保留基本方法 | 增加购买场景与业务价值标签；高意图题组提前冻结；把目标平台上的人工观察纳入正式计划 |
| 工单关联问题、样本、页面、事实与实验 | 保留并细化 | 在生成草稿前增加内容简报，说明缺什么证据、为什么改、如何承接咨询 |
| 事实库、内容审批、过期事实联动修订 | 保留 | 增加资料访谈与证据补齐任务，区分“客户确认”和“有可核验材料支撑” |
| 问题簇主页面、渠道变体、发布回执 | 保留并贯通 | 建立内容资产效果视图，串起同一主题的官网、渠道版本、引用、线索与下一轮动作 |
| 14 平台素材模板纳入分发 P0b | 收缩首版范围 | 首版只实现试点选中的 1—2 个分发渠道；其他模板进入后续需求池 |
| G5a 验收交付，G5b 完成观察结项 | 保留两道门禁 | 另设客户目标达成状态；结项完成与客户取得成效分别呈现 |
| Next.js Web、共享 TypeScript 业务层、独立 Worker | 延续已有方向 | 当前优先调整领域对象和运营流程；技术栈沿用已确定方案 |

## 二 把 GEO 成功写成可验收的客户目标

客户成功计划应在采样和内容生产前建立，明确：目标客户、产品与地域、优先购买场景、目标 AI 产品与入口、问题集、业务事件、预算、负责人、观察窗口、达标阈值，以及继续或停止投入的条件。

### 四层结果分别展示

| 结果层 | 要回答的问题 | 主要证据与指标 |
| --- | --- | --- |
| 交付结果 | 约定的内容和页面是否真正上线 | 批准版本、线上内容、URL、有效时间、工单验收 |
| AI 采用信号 | 目标产品是否出现了相关内容或品牌支持信息 | 原生引用、可核验的来源正文、品牌事实正确性；没有可观察来源时保留未知 |
| GEO 表现 | 在相关购买问题中，品牌是否更稳定地成为适合选项 | 固定非品牌题推荐率、高意图子集表现、引用与事实错误趋势，按目标产品分别展示 |
| 客户业务结果 | 是否带来有价值的客户行动 | 可观察的 AI 关联有效咨询、销售接受线索、商机或成交；来源强度与数据覆盖单列 |

这四层可以出现不同结果：某页被引用但未推荐品牌，品牌被推荐但没有可观察点击，咨询增加但成交尚未发生。页面应保留这些差异，帮助运营判断下一步。

### 建议的核心指标

**业务目标采用可观察的 AI 关联有效线索数。** “有效”由客户在项目开始时定义，例如符合目标行业或地区、存在真实需求、可联系，并排除重复提交、测试和垃圾咨询。保存销售接受或拒绝的原因。没有明确关联键时，不合并潜在重复记录，也不生成一个看似精确的客户总数。

技术可识别引荐、自报 AI 来源和来源未知分别呈现；活动链接只证明对应渠道或活动关联，不能单凭 UTM 认定来自 AI。该指标描述可观察关联，不能独自证明 GEO 带来的增量。

**前置信号采用目标产品的固定高意图非品牌题推荐率。** 保留现有 30 道非品牌题等权总览，在其中提前标记高意图子集，逐题计算后等权汇总。商业价值标签用于安排内容优先级，不事后改变指标权重。品牌事实题、比较题、探索题继续独立展示。

**护栏采用事实错误、采样与引用可观察覆盖、实际成本。** 不能通过减少可判断样本、改变问题或容忍错误主张取得表面增长。

新增指标需要进入下一版指标合同，确定分子分母、数据缺失处理、样本范围和版本；当前 metrics-v1 继续作为既有口径。

### 客户目标达成与观察结项分开

客户目标状态建议为“观察中、达到约定目标、未达到目标、证据不足、不可比较、已终止”。到期后按冻结条件判断，明确达成的是可见性目标还是业务目标。

可见性目标至少同时规定：目标产品与入口、固定题集、质量门槛、最低有意义的变化、持续性窗口和事实准确性要求。业务目标另加有效线索定义、来源证据等级、目标数量及成本条件。具体数值根据基线、客户经济性和可用预算确定，不设置适用于所有行业的统一涨幅。

G5b 仍允许实验以无改善或证据不足结项。规模化投入则应增加一道经营判断：预先约定的客户目标达成比例、持续交付成本和真实付费证据均满足要求。所有纳入试点的客户及退出原因都保留，不能只统计成功案例。

## 三 以购买场景组织内容运营

建议将运营主流程明确为：

客户业务目标 → 购买问题簇 → 内容与证据缺口 → 内容简报 → 制作审核 → 选定渠道上线 → 目标产品复测与线索复盘 → 继续、修订或停止。

### 购买问题簇

现有固定题保留，新增“目标客户、使用场景、购买阶段、关键约束、对应产品、业务价值依据、主要内容页面、承接动作”。问题优先来自真实售前、客服和销售记录，AI 用于辅助归类与补充表达。

同一购买意图的近似问法归为一个主题，避免通过大量相似题制造覆盖。原有逐题等权指标保持可追溯；主题视图作为额外诊断维度，显示每个主题包含的题数，防止题量较多的主题被误解为业务更重要。

每个问题簇必须明确客户产品确实适合的条件。客户缺少的能力，应反馈给产品或销售，内容不能补造能力来换取推荐。

### 在草稿前增加内容简报

把“选择任务后生成草稿”细化为“确认内容简报后生成草稿”。简报至少包括：

| 字段 | 必须表达的内容 |
| --- | --- |
| 目标问题与人群 | 要帮助谁，在什么场景做什么决策 |
| 当前观察 | 对应回答、引用页面和客户现有内容；区分已观察事实与原因假设 |
| 期望解决的缺口 | 缺事实、缺解释、缺案例、页面不可读、信息过期或缺少行动入口 |
| 核心回答与适用边界 | 产品适合什么情况，哪些情况不适合 |
| 证据材料 | 参数、测试方法、真实案例、演示或有出处的资料；标记来源与可公开范围 |
| 内容形式与目的地 | 优先更新哪一页，需要什么渠道版本，为什么选择该渠道 |
| 业务承接 | 对应演示、报价、咨询、门店联系或其他可实际使用的入口 |
| 验证假设 | 预计影响哪个问题组和指标，在什么窗口判断 |

缺少关键证据时生成资料访谈或补证任务，明确由客户哪位业务人员提供。事实审核解决正确性；内容简报还要解决内容对购买决策是否有用、是否提供了现有页面缺少的信息。

### 用内容资产组合覆盖决策过程

| 客户决策问题 | 优先内容资产 | 所需材料 |
| --- | --- | --- |
| 你是谁，提供什么 | 企业与产品事实页 | 实体名称、型号、服务范围、更新责任人 |
| 我的场景适合吗 | 场景解决方案页 | 适用条件、实施步骤、能力边界 |
| 与其他方案怎么选 | 选型或比较页 | 一致的比较维度、可核验资料、差异和限制 |
| 有什么证据证明有效 | 案例、测试或演示页 | 实际背景、方法、结果口径、适用范围 |
| 价格和实施风险如何 | 价格条件、交付、售后问答 | 有效政策、前置条件、例外与联系方式 |
| 下一步怎么行动 | 对应咨询或演示入口 | 有效表单、响应责任人、来源与事件记录 |

先盘点和改善已有内容，再决定新增页面。延续现有“一问题簇一主要页面”和过期事实联动修订设计；渠道稿件按受众与体裁适配，共用事实来源。

### 内容资产效果视图

以问题簇和主要页面为入口，聚合相关内容版本、渠道发布、引用证据、实验、线索及费用。每项资产应能回答：解决什么问题、用了哪些事实、哪些渠道上线、哪些目标产品观察到引用或推荐、下一次复查与修改是什么。

“页面被引用”和“支持品牌被推荐”分别记录。无法获得来源全文时保留引用事实，品牌支持性记为待验证；仅因 URL 相同不能把后续订单归到某个回答。

## 四 用实际样本选择平台与分发渠道

必须分别选择“客户希望影响的 AI 产品”和“准备发布内容的渠道”。前者按客户真实使用场景确定，后者结合该行业的引用观察、受众匹配、已有账号、内容适配与维护成本确定。

**将真实消费者端验证提升为相应客户目标的必选项。** 现有方案把 API 作为持续监测主体、消费者端作为小样本核验。若客户目标是豆包或其他 App 中的表现，正式基线和复测就必须包含该产品的独立观察计划：明确入口、模式、地区、账号与会话条件，冻结题目、次数、采样日与记录方式。

预算不足时先缩小承诺的产品和题目范围；消费者端数据不足时只报告探索观察。API 可以用于诊断与稳定追踪，其改善不能替代同名 App 的客户目标达成。现有每品牌每月 7,200 个自动计划样本应作为可选预算方案，由客户目标和通道验证结果决定是否采用。

**首版选择 1—2 个分发渠道。** 官网承担可维护的事实和主要内容；是否优先投入某个外部渠道，需查看目标问题下的原生引用、页面正文、账户归属和发布成本。一次引用只能形成候选依据，持续性需要后续观察。

现有分发报告将 14 平台素材模板列入 P0b，并估计分发与 SEO 增量 P0 共需 20—30 研发人日，已经指出不能直接塞回原八周计划。建议把首版模板、审核规则和验证限制在实际试点渠道，扩展其余平台前先证明现有渠道值得持续运营。[分发工作包与排期](客户网站SEO与中国大陆自媒体内容分发实施技术报告.md)

第三方行业报道、测评或合作方内容以真实材料和编辑采纳为前提；客户自有账号与转载继续按既有规则标识。运营可记录合作素材及发布结果，不把自有矩阵包装成独立第三方证据。

## 五 把复测结果转成下一轮动作

现有实验已经能记录改善、无变化、证据不足和不可比较。建议增加运营决策表，把下一步从自由文字变成有负责人、证据与复查时间的任务。

| 当前观察 | 优先核查 | 下一步动作 |
| --- | --- | --- |
| 上线后正文不可读、版本不一致 | 真实公开状态、正文、权限和发布版本 | 先修正页面或发布问题，再安排可比较观察 |
| 正文可读，尚未观察到引用 | 引用字段是否可观察、采样是否覆盖目标题、内容与问题的匹配、渠道样本 | 分清缺数与未观察到结果；补证据、调整内容或按预设规则延长观察 |
| 页面被引用，但品牌没有成为适合选项 | 引用段落是否支持品牌、适用条件是否明确、产品本身是否匹配 | 改善场景证据、产品说明或选择不同目标场景 |
| 推荐改善，未观察到有效咨询 | 数据采集是否缺失、渠道是否允许承接、页面是否有明确下一步 | 补测量或改善咨询入口；保留可能存在无点击传播的未知范围 |
| 咨询增加，但销售认为质量低 | 来源证据、需求与客户画像、内容承诺、销售处理记录 | 修订目标问题和下周期内容计划，明确筛选条件 |
| 推荐或引用下滑 | 原样本、模型/入口变化、采样覆盖、内容更新与竞品变化 | 判断是否可比较，再决定重测、修订或回滚 |

以上核查项是诊断路径，不能把缺少引用直接判为“未收录”，也不能把同期变化直接判为某篇文章的效果。

保留 14 天基线与原有窗口：D+7 观察第 1—7 天，D+14 比较第 1—14 天，D+28 检查第 15—28 天。持续性主要看后两个不重叠的 14 天窗口；D+7 与 D+14 不能充当两份独立证据。一个实验同时改官网和多平台内容时，先评估组合干预；需要比较渠道贡献时再设计分期或对照。

原设计已要求错误内容优先修复，建议在全流程中显式贯通这一分支：严重事实错误、失效联系方式或页面故障及时处理，同时记录干预，必要时重建基线。正常计划内优化继续遵守发布前基线门禁。

每次复盘产生一条策略记录：适用行业与场景、内容改动、目标产品、发布渠道、成本、样本范围、结果及下一步。初期以结构化人工记录实现；在其他客户或新窗口重复观察后，再将策略升级为可复用模板。

## 六 产品页面和研发优先级

### 建议的运营入口

| 页面 | 首屏应该帮助用户做的决定 |
| --- | --- |
| 客户项目总览 | 目标是否达成、当前证据是否足够、本周最重要的行动与客户依赖 |
| 购买场景与机会 | 哪些高价值问题值得投入，对应内容和证据缺口是什么 |
| 内容资产工作台 | 哪个主要页面要更新、缺什么材料、各渠道版本与审核进度如何 |
| 发布与维护 | 哪些内容真正上线，哪些失效或过期，谁负责处理 |
| 效果与实验 | 各目标产品的推荐与引用如何变化，下一步继续、调整还是停止 |
| 业务结果与报告 | 有哪些有效咨询或商机、证据强度、目标状态和服务成本 |

原始回答、计划运行、引用明细、官网日志和账号设置仍保留，作为可下钻的证据与管理页面。客户与运营的总览分别突出目标状态和待办，不让客户通过理解调度细节才能找到业务结果。

### 建议的实施顺序

| 优先级 | 内容 | 验收要点 |
| --- | --- | --- |
| P0 贯通目标 | 客户成功计划、购买问题簇与冻结题组 | 每项内容任务能追到业务目标；题目变更有版本 |
| P0 补内容决策 | 证据补齐任务、内容简报、主要页面与渠道版本关联 | 缺关键材料不会直接进入可发布稿；每项资产有用途和复测假设 |
| P0 验证真实结果 | 目标产品采样、发布验证、内容资产效果视图 | API 与消费者端分开；引用、推荐、业务关联能追溯到证据 |
| P0 形成运营闭环 | 有效线索轻量台账、目标状态、复盘决策任务 | 能记录未达标原因并生成下一步；成交数据不足时不编造收入效果 |
| P1 提高交付效率 | 已验证渠道连接器、批量维护、策略模板、更多客户复用 | 实际减少运营时间或提高验证质量，有成本记录 |
| P2 按需求扩展 | 其余平台模板与连接器、完整 CRM、更复杂经营能力 | 由付费需求和有效交付证据决定投入 |

沿用现有事实、机会、任务、内容版本、发布、实验、业务事件和报告对象。新增成功计划与简报的业务信息；主题到内容、内容到发布、实验到业务事件的关联优先扩展既有模型，避免出现两套状态与统计真相。首版线索台账支持授权导入或人工录入，复杂 CRM 集成后移。

## 七 首轮客户试点怎样执行

沿用一个垂直行业、3—5 家候选客户的方向。先用一家客户跑通交付方法，再按相同口径推进其他客户；单家成功不能代表方法已能稳定复制。

1. **冻结客户目标。** 确认适合的产品场景、目标 AI 产品、真实购买问题、有效线索定义、公开资料负责人、可改页面和预算。业务数据无法取得时，明确只能验收可见性目标。
2. **盘点内容与建立基线。** 在现有 40 题结构内确定商业意图，开展 14 天基线；并行完成内容盘点、资料访谈和简报，正常实验内容待基线完成后上线。
3. **交付首批内容组合。** 延续每品牌至少 3 项可复核改动，围绕少数明确场景形成主要页面、证据材料和承接入口；外部分发采用选中的渠道。具体数量按缺口决定，文章篇数只作工作量记录。
4. **持续复测与处理线索。** 按原窗口观察目标产品，定期由运营、分析师与客户核对证据和有效咨询。销售反馈进入下一轮内容任务。
5. **按预定条件决策。** 保留改善、未改善和未知结果；区分交付签收、观察结项、目标达成、是否续费。若需延长观察，登记新窗口、原因、预算与最终停止时间。

现有“八周产品交付”与“客户内容生效观察”继续分开。第 5 周上线的内容，其 D+28 会进入第 9 周或以后；调整首版范围后仍需重新估算研发、运营和客户配合容量。

### 一个示意项目

以原方案中的设备管理软件为例，目标场景可以是“多门店需要私有部署和分级权限”。目标事件选择预约演示或合格咨询。

运营先核实客户是否确有这些能力，并取得部署条件、权限说明及可公开案例。首批内容可包括更新场景页、补充有测量条件的真实案例、完善部署问答与演示入口，再在经样本支持的渠道发布适配版本。

复盘分别查看：线上材料是否正确、目标 AI 产品在相关问题中是否将品牌列为适合选项、是否引用了相关证据，以及是否有符合客户画像的咨询。若场景页被引用但品牌仍未被推荐，应检查品牌与场景的支持证据；若已推荐但咨询不可观察，应先检查业务承接与数据覆盖。该示例是执行方法，未代表已有客户成效。
