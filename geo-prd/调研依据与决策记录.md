## 4. 产品决策记录

| 决策 | 当前方案 | 重新评估触发条件 | 决策责任 |
| - | - | - | - |
| D01 主架构 | 用户确定 Next.js 全栈；共享 TypeScript 业务层与独立 Node.js Worker，开源模块适配复用 | 框架方向已定，PoC 用于调整组件、实现边界与工期 | 用户确定方向；技术负责人落实 |
| D02 监测范围 | 两个已实测 API 通道为试点目标，最低一个可交付 | 权限不足、成本超预算或数据不可解释 | 产品与技术 |

| D04 官网数据 | 脱敏日志/聚合数据导入优先 | 稳定客户需求证明持续连接器能降低交付成本 | 产品与交付 |
| D05 发布 | 修改包、素材包、客户审批与 URL 回填；CMS 为 P1 | 实际授权可用且节省人工足以覆盖维护 | 内容与技术 |
| D06 选型授权 | 许可文件、素材权利、依赖分别核对 | 引入代码、升级版本、改变部署或分发方式 | 技术与商业负责人 |
| D07 阶段结项 | 第 8 周交付结项和 D+28 观察结项分别记录 | 发布延迟、采样故障、环境变化 | 交付与分析师 |

## 5. 执行时补充的证据模板

每次 PoC 记录：仓库 URL、tag/commit、日期、运行环境、配置摘要、许可文件位置、执行人、用例、原始输出位置、费用、失败、差异、结论和复核人。凭证只记录密钥引用，不写入文档。

每次需求决策记录：问题、候选、依据等级、选择、成本影响、客户影响、负责人、复议条件。若后来实测推翻 README 或调研说法，应保留旧记录和变更理由，不覆盖历史证据。
