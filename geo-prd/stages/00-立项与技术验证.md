# 阶段 0：立项与技术验证

计划时间：第 1 周｜门禁：G0｜主要负责人：产品/交付与技术负责人｜前置：无｜后续：[阶段 1](01-租户品牌与证据底座.md)。

## 目标与输入

回答三个问题：客户愿意为什么结果付费，哪些渠道能提供可信样本，Next.js 全栈方案如何在资源内完成交付。用户已确定 Next.js，组件与代码组织见 [架构文档](../Next.js全栈技术选型与项目架构设计.md)。阶段结束输出试点章程、组件兼容与复用决策；没有有效渠道证据时不进入完整平台开发。

所需输入：候选行业、3—5 家候选客户及公开产品资料、可修改的官网或内容渠道、供应商试验账号、费用上限、团队技术能力。缺少客户或账号时先做离线数据结构与公开材料审查，对缺失输入登记阻塞，不制造实测结论。

## PoC 实施方法

主底座先选 1 品牌、10 个非品牌问题、2 个通道、每题 3 次，形成最多 60 个计划样本的首次探针。之后按发现的问题补样，不把这个小规模探针当效果实验。渠道比较尽量使用同题和接近时点，不注入客户事实库。

候选 API 优先验证火山方舟联网搜索与百炼联网搜索；豆包助手独立评估，不能默认已开通。消费者端选 10 个相同问题人工采样，记录时间、入口、模式和会话条件，输出差异案例，不计算“API 等价率”后宣称一致。

模块复用评价建议权重：证据完整性 25%、国产适配扩展 20%、隔离与权限 20%、运行恢复 15%、移植维护复杂度 10%、交付体验 10%。每项以复现记录评分；许可不明、原始证据不可保存、跨租户隔离无法补齐是硬阻断，不能用总分抵消。该评分不再用于重新选择应用框架。

对 GEOInflow 使用脱敏测试日志和固定页面清单，包含成功、失败、重复、未知 UA、日志缺口，核对“没有日志”是否被错误显示为“无人抓取”。对 GeoLook 使用同一组样本检查诊断如何变为有验收条件的任务。研究流程不要求将其完整程序嵌入最终系统。

固定 tag/commit，记录环境、耗时和失败；不将客户密钥写入仓库。代码与文档/图片许可分别核对，特别是 GEO Doctor、GEORank；GoodieAI 的许可未确认前只观察公开产品流程。来源见 [调研依据](../调研依据与决策记录.md)。

## 渠道能力矩阵模板

每行包含：channel_id、实际服务/端点、模型/版本、是否联网、联网触发证据、能否强制、原生引用字段、搜索候选字段、地区能力、采集许可依据、限流、费用、失败状态、原始样本链接、复核人、通过日期。未知字段填 unknown，不填默认“支持”。

引用字段缺失的通道可以通过“回答监测”验收，但其引用指标必须为 N/A；只有通过引用专项验收的通道才展示引用率。自建搜索+模型链路只能进入自建实验类别。

## 交付物与 G0

- 试点章程：行业、客户、任务目标、套餐假设、预算、人员、数据授权、客户配合事项。
- 选型记录：固定版本、采用与拒绝理由、缺口、自研范围、许可待办、切换条件。
- 一组可复核真实响应与人工样本；不能只提交仪表盘截图。
- 经评审的指标合同、固定题模板、成本模型和降级方案。

G0 通过条件：至少一个 API 通道完整保存真实回答、采集条件与费用依据；引用能力明确为支持或不可观察；选型没有未解决的复用授权阻断；客户和人员有具体落实路径。仅一个通道通过时允许缩小试点，但产品页面必须说明覆盖范围。

建议开发投入 5—7 人日，产品与数据工作并行；只是容量估算。第 1 周无法获得账号或客户时，不将等待计成验证完成。可继续离线合同和原型，但基线起点与后续观察整体顺延。
