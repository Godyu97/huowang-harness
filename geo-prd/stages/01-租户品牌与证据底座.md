# 阶段 1：租户品牌与证据底座

计划时间：第 2 周｜门禁：G1｜负责人：技术负责人｜前置：[G0](00-立项与技术验证.md)｜后续：[阶段 2](02-监测调度与指标质量.md)。

## 目标与输入

完成“一个客户能录入事实与固定题目，采到一个真实回答，并从原文检查结果”的纵向流程。建立数据边界后启动 14 天基线，不等所有页面完善再开始积累样本。

输入包括 Next.js 全栈 PoC 锁定的组件版本与模块复用清单、角色表、真实响应样例、指标合同、试点品牌资料、已确认的通道和预算。工程结构遵循 [Next.js 架构文档](../Next.js全栈技术选型与项目架构设计.md)。此阶段不需要客户提供全站管理员账号。

## 数据与接口要求

核心实体遵循 [指标与证据合同](../指标与证据合同.md)。租户约束不仅靠前端隐藏：每个带 tenant_id 的关联都校验父子租户一致，包含样本、引用、事实、任务和对象存储索引。后台 Worker 从任务中解析并验证租户，不信任请求端直接传入的品牌归属。

建议先提供品牌/事实/题集 CRUD、冻结计划、触发单次样本、查看样本、纠正分析和申请导出这些接口。修改接口记录操作者与对象版本；导出通过租户鉴权后生成限时访问地址。对象存储不开放公共目录浏览。

事实批准与内容批准是两个对象：事实批准仅说明该事实可用于指定范围，不等于允许发布任何生成内容。撤销事实时能查出关联草稿；监测请求只使用冻结问题与采集配置，不附带事实库。

## 最小用户流程

品牌管理员建档并确认名称 → 运营录入来源资料 → 分析师冻结题集 → 查看采样费用预估 → 启动样本 → 查看回答与引用 → 人工复核实体标签 → 查看该版本指标。首次成功后再扩展批量与列表体验。

页面应直接显示下一步：无事实时提示补资料；无问题时提示配置题集；权限失败时提示修复对应通道；正在采样时展示进度和已有证据。没有结果不能展示 0% 推荐率。

## 基线启动操作

1. 品牌方确认 40 道固定题与竞品集合；分析师检查非品牌题没有暗含目标品牌。
2. 冻结通道、模型/未知状态、工具、地区、时区、每日次数和槽位；40×2×3 为每天 240 个计划样本。
3. 明确起止时间及 14 个完整自然日；记录计划版本、题集 hash 和预算。
4. 调度未完成时由运营触发同一适配器，记录实际时间和对应槽位；人工 App 样本另存。
5. 缺采必须保留，超过比较门槛则延长或重新建立窗口；切换底层通道时形成新基线。
6. 与客户约定目标页面在基线期间的变更登记；紧急业务改动可以做，但受影响题/页面标记混杂，必要时重开实验。

## 验收与 G1

验收由技术、分析师和试点管理员共同完成。用两个测试租户、代理商的已授权/未授权品牌验证读取、修改、导出和对象链接；猜测 ID 不能越权。验证旧事实撤销、同名品牌、题集更新、原始记录不可覆盖及分析重算。

G1 条件：一个完整品牌已跑通真实采样与证据复核；核心权限用例全部通过；题集与计划冻结；基线开始时间可查；失败与未知状态不混为零；没有私密资料流入监测请求。完整调度和高级图表不是 G1 前提。

交付物：数据库迁移、角色与接口合同、建档说明、原文查询页、最小可用演示、基线登记表、访问隔离检查结果。建议开发投入 8—10 人日；如果基础权限补齐超过容量，应减少页面装饰与非核心字段，不能取消隔离。

## 风险与交接

底座只支持单工作区时先补授权边界，不能用“试点客户少”作为隔离豁免。品牌资料迟到时该客户单独延后；不影响已完成 G1 的客户持续采样。

向阶段 2 交接冻结计划、原始响应契约、样本状态和预算账户；向阶段 3 提供只读事实与页面清单，提前准备审计但不发布实验改动。
