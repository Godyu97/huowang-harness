# 阶段 4：内容审核与发布

计划时间：第 5 周｜门禁：G4｜负责人：内容运营、品牌管理员｜前置：[G3](03-诊断与优化任务.md)｜后续：[阶段 5](05-复测归因与试点验收.md)。

## 目标与输入

将首批工单转成经过事实核验和客户审批的真实页面或渠道内容，保留版本、回执、公开 URL 与实际发布时间。每品牌至少完成 3 项可复核改动；文章数量不是唯一交付标准。

输入：已批准事实、具体工单、基线结束记录、实验计划、客户发布方式和权限。无自动发布权限时由客户或授权人员在原渠道发布，平台导出素材包并回填证据，不阻断业务闭环。

## 内容生产与审核细则

页面采用“回答问题、适用条件、具体证据、限制例外、更新日期”的结构。题目可以相同，渠道措辞可以不同，但参数、价格、适用对象和服务承诺保持一致。模型只可从已批准且允许外发的事实生成公开内容。

自动校验不仅检查 fact_id 存在，还检查主张与事实值/单位/条件相符；主张与事实无法自动匹配时交人工复核。不得用虚构测评、客户证言、资质或第三方引用补足证据。涉及专业判断的内容不因系统审核通过而自动视为业务事实。

每次提审固定内容版本，显示改动、关联事实、目标账号和拟发布时间。审批可驳回、批准或要求修改；评论不等于批准。稿件批准之后若事实撤销/过期、账号改变、发布正文改变，必须重新校验并在必要时重新审批。

## 发布状态与异常

状态分为：draft、in_review、approved、awaiting_confirmation、submitted、platform_review、public、rejected、withdrawn、unknown。手工发布同样使用状态和版本记录；截图不能替代可访问 URL，但平台确无公开 URL 时可保存远端 ID 与访问条件，并明确验证限制。

自动提交使用发布幂等键：tenant + channel_account + content_version + requested_operation。请求超时进入 unknown，先按远端 ID/幂等支持查询，无法查询则人工核对，禁止盲目重发。正文没有变化但更换发布账号仍属于新操作，需要对应范围确认。

撤销授权后停止待执行任务，不再刷新令牌；已公开内容不会因此自动消失，撤回作为独立操作。令牌只保存在密钥存储，内容生成模型、日志和素材包中不得出现。

## 各渠道的交付范围

| 渠道 | 首轮方式 | 接口升级条件 |
| - | - | - |
| 客户官网 | 页面修改包、必要时补丁/PR，由客户部署 | 明确仓库/CMS 权限、回滚与审核流程 |
| 单个 CMS | P1 创建草稿；正式上线单独确认 | 凭证范围、草稿/正式发布权限、重复提交和回执验收 |
| 公众号、小红书、头条/搜狐/网易等 | 素材包、人工发布、URL 回填 | 针对具体平台和账号证明实际开放能力 |
| 抖音等视频渠道 | 脚本/素材说明与人工发布记录 | 具体应用资质、发布权限和平台流程验证 |

本阶段不以“登录成功”判断“可发布”。各平台当前能力的依据和未核验项见 [调研记录](../调研依据与决策记录.md)，接入时重新核验。生成内容的声明、标识与审核记录应随素材包和发布流程保留，具体要求按产品形态评估。

## 验收与 G4

验证正常批准与发布，也要验证：批准后改稿、事实过期、无权限账号、授权撤销、平台拒绝、提交超时、重复点击、公开页面与批准版本不一致。所有用例都应有可解释状态与处理动作。

G4 条件：每个试点品牌至少 3 项已上线、执行验收通过的改动；关联工单、内容版本、审批、URL/远端 ID、时间及验证结果；未出现未经批准内容发布。不能由客户按期发布的项目标为阻塞并顺延，不用导出素材包替代“已上线”。

交付物：批准草稿、素材/修改包、发布账本、验证结果、回滚说明、实验窗口与 G4 记录。建议 P0 开发 6—8 人日；CMS P1 另估 2—4 人日，只有剩余容量足够才加入。

## 交接与回滚

交接阶段 5 的关键是实际上线时间和内容版本，而不是计划发布日期。同一实验多个页面分批上线时，逐页记录；统一实验窗口须以预先约定规则对齐，不能挑最有利日期。

公开内容发现错误时优先修正或撤回，同时记录错误、影响范围和回滚版本。修复可能改变实验干预条件，分析师据此标记实验不可比较或新开版本；不能为了保持实验数据而保留错误内容。
